# 原型功能落地：真实目录检索与对比（2026-11-15）

## 目标与范围

用户已确认本阶段先落地真实目录检索、筛选、对比、档案和来源；预约等合作及权限条件具备后另做。

面向为家属查找广州养老机构的人，在已有235家真实目录中完成“输入多个线索→筛选→比较2至3家→打开档案→核对来源”。成功标准是全程只显示官方快照可证明的字段，查询与对比可复制URL，刷新/回退后状态仍可还原。只做根应用的只读能力，不触碰 SHA 锁定的 `prototype/` 演示，也不开放预约、认领、榜单、价格、当前空床、商户与管理后台。

## Source of Truth 与边界

`data/raw/family_fields_official.csv` 与 `data/raw/id-map.json` 仍是235家名单及稳定ID的唯一输入；`scripts/build-data.ts` 校验后生成同版 `data/generated/guangzhou-institutions.v1.json`。`lib/catalog.ts` 为页面提供构建期快照。`q`、`district`、`page`、`compare` 都是URL中的临时视图状态；不设账户、浏览器收藏数据库或写接口。工商快照仍仅供本机私有预览。备案床位只显示名单发布时的登记规模，不能当作空床。机构/服务能力、费用、长护险、品质评级没有足够来源，不纳入筛选和对比。

## 模块、接口与数据流

- `lib/search.ts` 负责查询字符串规范化、词组AND匹配、区筛选、官方序号排序和20条分页。空格分开的词可分别命中机构名称、区或地址；每词都须命中。过长、非法区、非法页码继续给出显式纠正信息。
- `lib/compare.ts` 只解析/校验逗号分隔的稳定机构ID，去重并限制至多3家；未知ID跳过并报告。生成规范 `/guangzhou/duibi/?ids=...` URL，不接收其他字段值。
- `components/DirectoryView.tsx` 在原有列表页组合结果、URL中的对比选择与状态提示。勾选框选中后更新当前URL的 `compare` 参数；翻页和再次筛选保留选中机构。第4家不可加入，提示先取消一家。
- `components/ComparisonView.tsx` 从同一份目录快照读取选中的机构，在对齐的表格列中比较名称、区、地址、备案床位、联系电话与三项预收费标记，并逐列链接档案、源表序号和来源说明。移动端横向滚动，保留可见的表格说明。
- 无新API、权限或持久写入；数据流为官方CSV→构建校验→静态目录快照→客户端URL筛选/对比→静态档案及来源链接。所有页面继续受现有静态导出和noindex约束。

### 浏览器缺陷回修：对比→档案→返回列表

### 浏览器缺陷回修：快速选择与键盘移除

2026-11-15根代理用Chrome headless在127.0.0.1:3210复现两项真实失败：对全部含 `_rsc` 参数的请求延迟300ms，从空选择连续点击前两家且不等URL，最终只剩 `compare=gz-000002`、1项选中，网络记录显示两次请求分别基于第一家和第二家单选；对比3家时聚焦首列移除按钮并按Enter，剩2家后焦点退到BODY。前者由事件基于上一轮渲染的 `selection` 发起异步导航引起；后者由移除焦点所在DOM后缺少焦点交接引起。

Next.js 15官方文档“Linking and Navigating / Native History API”（https://nextjs.org/docs/15/app/getting-started/linking-and-navigating#native-history-api，2026-11-15访问）明确 `history.replaceState` 与 `useSearchParams` 集成。本轮将目录勾选/清空及对比移除的同路由视图参数更新改为原生 `replaceState`；事件内每次读取实时 `location.search`，不再根据过期渲染值累积，也不增加服务端导航。展示仍由 `useSearchParams` 驱动，URL仍是唯一状态源。目录调用的 `SearchForm` 即使尚未选择也保留隐藏 `compare` 节点，原生GET提交前从实时URL同步该节点，保证刚勾选立即筛选或刚清空立即筛选；首页未传此参数时仍不输出隐藏节点。

对比移除使用组件局部按钮ref、待交接目标ref及依赖选择值的effect；URL新选择呈现后聚焦相邻剩余机构的移除按钮，最后一家移除后聚焦“返回目录选择机构”。数量行始终可见并用polite status播报，包括0家。不使用全局DOM查询、任意延时、持久库或额外选择状态副本。
