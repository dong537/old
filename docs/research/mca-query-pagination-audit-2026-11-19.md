# MCA 全国列表口径、重叠与分页可靠性独立审查（2026-11-19）

## 结论与证据范围

当前 first/followup 代码明确提交“地区 + 页码/页长 + checkSort=1”，没有补贴、空床、名称、机构类型等显式子集过滤；已有缓存同时出现补贴标识0与1，支持“未限定补贴参与机构”的判断。**这不证明该端点覆盖全国所有机构，也不证明checkSort在服务端绝不改变可见集合。** 所存前端代码把checkSort用于入住率排序，未提供唯一ID次序、游标或冻结快照。当前能交付的是分口径、分时段的观察集合，不能把API total等同实际采到全量。

本轮只读现有私有响应/官网JS、生产代码与测试，未发MCA请求、未改tree validator/恢复脚本/运行状态；不负责四级overlay或详情字段语义。新增3个离线请求契约回归测试，未新增生产采集路径。

## 查询口径：明确排除什么，尚未证明什么

| 证据 | 复核结果 | 可得结论 |
|---|---|---|
| fetcher.page_params(page, code, True) | 恰为 current、size=10、areaCode、checkSort=1 | first/followup固定显式参数；不提交ahae0635/emptyBed/关键词/属性筛选 |
| 93份真实历史列表页 | 72页checkSort=1；21页未带排序；全部未带ahae0635，参数键无其他筛选 | 两种排序口径须分开审计，不能无标记混算 |
| 894行原列表 | ahae0635=1有837行，0有57行 | 该无补贴参数请求至少返回两类记录；数值是重复观察行数，不是唯一机构数 |
| 官网FilterPane | “仅显示补贴参与机构”绑定ahae0635；默认checkBoxValue含2；页面初始filterParams含ahae0635=1 | 网页默认勾选口径与当前采集口径不同 |
| 官网排序 | checkSort标签为“入住率”；levelSort/priceSort分别为星级/价格 | 排序用途有前端证据，但缺服务端集合不变/唯一排序保证 |

同一“无显式补贴筛选”不等于“无任何地区限制”，也不等于“所有登记/运营/未公开机构”。后端默认范围、上架状态、缺失机构与全量定义仍未知。列表类型字段只按原始返回保留，本审查不扩展其详情同名字段语义。

### 页大小100的原件口径修正

`data/private/mca-institution-list-retry-2026-11-18/page-1-request-size-100-sanitized.json` 保存的实际参数是 `{current:1,size:100,ahae0635:1}`，没有areaCode；服务端size=10、total=35644、10行，捕获于2026-11-18T12:27:50.792135Z，文件SHA `702b68d8fdb2ccd8665296717265d66abe5e9b4ebe9e53e0ac59a728ba9ca379`。相邻size=5请求返回size=5、5行、同total；文件SHA `7c1fcb2fd2ef8658e0e2a9205604d2d1a074bc6615ef77d6c5c91179915d63a6`。

这是**全国补贴筛选的脱敏历史样本**，不是广东无补贴筛选原HTTP字节。它支持该样本中100被压至10，不能证明任何端点/口径永远硬上限10。当前93主缓存则均为请求10、返回10。不要再把此size100证据写成广东无筛选实测，更不能将35644与下述39250直接相减称为漏采。

93页合计894行、738个不同axbe0001，156是跨页/跨轮/跨地区累计重复观察次数，不能统称156家异常机构。按35地区、41独立capture审计：

| 指标 | 结果 | 含义 |
|---|---:|---|
| capture有缺页 | 34/41 | 预计页号未收齐；不是空记录 |
| capture有跨页重复 | 2/41 | 广东默认排序与北京checkSort=1 |
| 同capture跨页/同口径跨capture可见total漂移 | 0 | 现存样本未观察到；稀疏首屏和不同时间窗口不能证明总量不变 |
| 缺原HTTP字节 | 93/93页，41/41capture | wrapper有SHA字符串但无rawBodyBase64；不能重构原件验证其SHA |
| 严格pageEvidenceComplete | 0/41 | 即使收齐小区县页，也因原文缺失而不满足当前门禁 |
| 全国零遗漏证明 | false，nationalTotal=null | 无冻结快照/唯一ID顺序，父级直属残差未穷尽 |

具体真实片段：
- 广东默认排序：total=1422、143预计页；现有20页（1—16、27—30）200行/145 ID，55次重复观察。各已存页total都相同，仍存在明显重复。

现有保守审计 `audit-mca-list-coverage.py` 已将 total漂移、size漂移、缺页、重复、页长、原文、manifest哈希及未知冻结顺序分开。大页模式的“页码观察完”与稳定唯一集合不同：large模式允许继续积累不稳定页，但 `areasUnverified`/快照未验证必须保留，不能把exit0映射为全国完整。

## 父子范围重叠与直属缺口

- 同checkSort=1，已存北京省级259 ID覆盖东城16 ID中的全部16；这16是预期祖先/后代重复，不应计为32。省级相对东城多243 ID，不等于243家省直属：省级捕获中原areaCode恰等于北京父码的ID为0；还有15个官方编码子区没有相应缓存。
- 广东默认排序145 ID与番禺默认首屏10 ID交集为0。广东仅20/143页，不能据此否定父子包含，也不能把两个集合当互斥分片。广东排序根首屏与番禺小样本同样不足以做全量对账。
- 32个根首屏合计310行/310不同ID，根首屏之间未见重叠；这只是每根最多10行。原areaCode直接等于根查询码的已见ID至少6个：吉林1、广东2、宁夏3。只合并市县分片会丢掉这些已见直属记录；6不是直属总量。
- 新疆与兵团首屏尚不能证明集合互斥；兵团该时点total=0且存有空首屏，只能标记该查询观察为空。严禁按65前缀归并或直接累计各级total。

## size=10 的成本与阶段遗漏

32个历史根首屏的total算术和为39250，仅是不同时间查询的报告数之和，**不是全国机构数**。按每根独立算 `max(1, ceil(total / 10))`，名义需要3940个列表POST页；其中兵团total=0仍需1个首屏作为空结果证据。32首屏之后的名义页差为3908，不能当作现代队列真实剩余请求，因为旧页缺原文，且现代种子/快照不可混入旧capture。

- 3940个POST在每个站点请求至少60秒、每小时最多60请求下，仅POST理想下界为65.67小时；3908页差为65.13小时。两者都不含校时HEAD、0—10秒抖动、网络、冷却、错误重试/恢复、第二轮对账、全部市县/直属观察。不能作为交付ETA。
- 当前首屏batch最多20请求且校时HEAD也消耗预算；followup每批12请求、最多5地区，所以“20请求=20页”“12请求=12页”均不成立。
- 31个正数根的total全部>30，最多河南3791（380页），均不能由small的2—3页模式补全；必须进入large（4—5000页）阶段。空根首屏不进入续页。
- 任何未来地区超过5000页，会被large上限排除并计为skipped；该地区必须仍是覆盖缺口，不能只依据选中队列结束宣称全国完成。
- 全部市县的首屏尚未采集，无法给出实际全国多层POST总预算；父子查询会重复观察同机构，叠加各层total只能用于请求成本估计，不能用于机构数量。
