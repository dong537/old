## 递归分片与数据归属

1. 以 32 个一级节点建私有分区台账。后续若获准继续低频采集，再按官方区划树的节点 id 读取子节点，验证 pid、层级、代码唯一性及无环关系；广东的下一层已有 21 个市级节点。市级、区/县级以及更低层是否需要展开，以官方树实际返回为准，不靠代码前缀臆造不存在的节点。
2. 每个节点以该节点 sbcode 为 areaCode 查询。保存请求参数、响应时间、页号、原始总数和每页 ID；原始行同时保留其自己的 areaCode。查询范围与行归属是两件事：广东省查询已返回区级行，说明至少该省查询包含后代行；其他节点须逐个验证，不预设全站相同语义。
3. 若某节点分页漂移或跨页重复，沿**已确认的官方子节点**递归拆分。每层必须另外留出“本节点直挂”集合：原始行 areaCode 等于本节点 sbcode。市级直挂也不能靠区县汇总获得；如果父节点无法稳定分页，又没有明确的精确直挂查询或官方导出，就不能证明这一集合完整，节点应保持未完成。
4. 同一机构用原始 axbe0001 去重；名称相同不能自动合并。一个 ID 同时出现在祖先查询与子孙查询是预期的跨层观察，应保留两份来源记录但只计一个机构；同级互斥子树之间出现同一 ID、或同一 ID 对应多个互斥 areaCode，应隔离复核，不能静默去重后宣称对账通过。新疆与兵团尤其要用官方 id/pid 关系和 ID 集合核对，不能只按前缀判定归属。

## 每个节点的验收条件

- **请求与缓存：** 每页 areaCode、排序参数、页号、服务端页大小与台账一致；HTTP 200、业务码 0；原始响应哈希、抓取时间、失败和限流状态可追溯。遇到 429 或站点冷却即停止，不能换分片绕过。
- **分页：** 响应 total、实际 size 跨页一致；预期页都在；末页长度正确；页内/跨页 ID 不重复，去重后 ID 数等于该分片稳定的 total。单次去重数相等仍需留意动态 offset 漂移。
- **复核：** 在允许的请求预算内比较独立轮次的总数、每页 ID 集和全集；不一致即标记漂移并停止该分片的完成判断。两轮一致只能说缓存重复性通过；没有服务端冻结快照、唯一 ID 排序或稳定游标时仍置 snapshotVerified=false。
- **地理归属：** 行的原始 areaCode 必须能映射到该节点或经官方树确认的后代节点；未识别代码不靠名称或纯前缀强行归属。遍历台账时每个官方子节点只出现一次，且无缺失、孤儿和环。
- **层级对账：** 父节点完整 ID 集应等于“本节点直挂 ID 集 ∪ 各子节点去重 ID 集”；子节点 ID 应是父节点 ID 的子集，同级子节点应无异常重叠。只有各集合都可信且为同口径时间窗口，才比较父级 total 与联合集合大小。单纯把各子级 total 相加，既会遗漏直挂，也可能重复计数。
- **全国对账：** 32 个一级分片均达到上述条件后，再将其去重联合与**同时间、同筛选口径**的全国总数比较。此前全国接口曾报告 39,384，仅是当时的参考口径，不能与未来批次总数直接相减来声称缺口。

列表完整性与详情完整性分开验收：每个唯一 ID 需分别记录详情端点成功/失败、字段缺失、冲突与资料日期；取得列表不等于取得了详情，更不等于取得公开再展示许可。私有预览与网站数据继续隔离。

## 当前阻塞与判定

当前缺全国市/区官方子树、各省稳定总量、父级直挂完整集合，以及可证明不漂移的服务端快照或唯一排序。广东省原始缓存已实际违反分页唯一性；三个小区/县两轮一致不能外推到全国。除非取得稳定游标/快照、官方批量原件，或为每个分片建立可核的完整性证据，否则应报告“已观察的私有分片覆盖”，不得标记“全国完整”或把这些记录直接发布为最新在营机构目录。
