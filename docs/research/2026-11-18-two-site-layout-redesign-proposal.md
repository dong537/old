# 养老信源前端布局改版计划草案（2026-11-18）

此文件是 2026-11-18 的方向草案；用户随后批准执行。正式范围和设计取舍见 `docs/superpowers/specs/2026-11-18-source-led-frontend-redesign.md`，2026-11-19 的移动端补核见 `docs/research/subagents/two-site-mobile-layout-2026-11-19.md`。下文保留草案阶段的证据状态，不冒充最终验收。

## 目标与范围

- 用户：为家人查找养老机构、核对资料的访客；核心任务是选地区、查记录、看可用事实、追溯来源并继续联系核实。
- 成功标准：首屏能开始查找；列表只展示有依据的可筛选维度；详情把机构信息和证据放在同一阅读路径；手机端导航和操作完整可达。
- 改版范围：公开前台的共享页头、首页、广州及全国机构目录、结果卡、机构详情、来源说明；次级指南与来源页统一到新视觉系统。独立 prototype、私有预览和后台不纳入这轮视觉改版。
- 保留现有路由、静态导出、真实数据读取、来源分级、隐私遮蔽、未知值语义、URL 筛选与返回路径。暂不新增在线预约、商家入驻、实时报价、空床、未经证实的地图点位。

## 推荐方向

采用“城市入口 + 官方核查工作台”的混合布局：面向家属的首屏借用商业目录的地区直达和结果可扫读性，搜索与服务分组借用民政部平台的任务导向；本站的独特核心是每条记录的来源、资料期与未知项，不把不同来源合并为一份已核验机构资料。

备选方向 A 是直接以全国目录列表作首页，步骤更短但不利于解释广州官方名单与全国来源线索的差别；备选方向 B 是仿门户首页铺满服务入口，覆盖面广但会把未开放能力推到首屏。推荐混合方案，后续用两套低保真线框验证导航与首屏信息顺序后冻结设计。

初步页面骨架：

    页头：品牌 | 找机构 | 核对官方来源 | 服务指南 | 来源说明
    首页：地区选择 + 名称/地址搜索 → 广州官方名单与全国线索的明确入口 → 常用地区 → 核对步骤
    目录：范围/来源标题 → 地区、关键词及有数据支撑的筛选 → 结果数 → 记录卡 → 分页
    档案：名称与位置 → 可用事实/联系出口 → 字段来源和资料期 → 其他记录/核对建议
    手机：搜索框和地区选择纵排；筛选用可见按钮展开；结果与来源说明单列

## 实施顺序

1. 固定现状：盘点公开路由、共享组件、数据字段及已有未提交改动；以桌面、320/375px 截图记录首页、目录、档案的当前状态。补看两站可访问的列表/详情与移动版；无法访问的页面标注证据缺口，不猜布局。
2. 形成设计契约：出“保留/替换/删除”清单、两套首页与目录线框、任务路径、组件状态及视觉 token；以真实机构记录和长名称、缺值、零值为内容样本。先确认方案，再替换旧的 dist(1) 视觉权威说明。
3. 改公共壳与首页：先实现导航、地区/关键词首屏搜索、真实可用的入口及适老化尺寸；校验静态路由和 320px 无横向溢出。
4. 改目录与档案：统一全国线索、广州官方名单、官方来源三个不同口径的结果结构；仅显露已取得且可核的筛选字段。卡片优先显示名称、地区、地址、实际可用字段和来源；详情将证据紧邻字段，保留联系与返回路径。
5. 收敛次级页面与验证：服务记录、长护险指南、来源规则沿用新组件及层级；完成类型检查、相关测试、静态构建和真实浏览器路径验证。覆盖 320/375/768/1024/1440px、200% 缩放、键盘焦点、空结果、加载/失败、长文本和来源跳转，保留改前/改后截图。

## 数据与风险边界

- 企查查线索、地方官方来源行、广州官方名单及民政部站点信息仍由各自现有数据文件/模块负责；前端只编排展示，不把同名条目自动认成同一在营机构。
- 民政部平台当前无经验证的完整可再展示快照；设计可参考其交互层级，不从其页面反推本站已拥有价格、空床、星级或资格字段。未知、无数据与数值 0 分别呈现。
- 工作树已有大量未提交改动；实施时先识别归属并小范围修改，禁止广泛重置、覆盖或重写既有数据流程。
- 当前外部页面证据不足以确认完整移动体验；这部分必须在设计定稿前补查或明确标为未验证，不能将桌面固定宽度直接移植。
