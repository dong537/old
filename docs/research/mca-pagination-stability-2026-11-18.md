# 民政部平台机构列表分页稳定性小样本（2026-11-18）

## 目的与范围

只用少量已完成的匿名列表请求，验证广东省 `areaCode=440000000000`、不启用 `ahae0635` 补贴筛选时，分页是否可直接组成完整快照。接口本轮返回 `total=1,422`，服务端把请求 `size=100` 强制限制为 10。下述仅比较机构内部 ID `axbe0001`，未在文档写入联系人、电话或逐家记录值。

## 官网公开页面的排序参数

从官网懒加载脚本 `https://yanglao.mca.gov.cn/js/chunk-3d5896b7.22ca4f71.js` 的 `FilterPane` 读到三个实际提交字段：`levelSort`（星级）、`priceSort`（价格）、`checkSort`（入住率）。点击各排序项时取值在 `1`、`0`、空之间轮换；筛选改变后提交给列表查询。该脚本不提供按机构 ID 的明确稳定排序，也不能据此推断服务端在同值时的次级排序。

## 已完成请求的观察

| 请求口径 | 样本 | 观察 |

| --- | --- | --- |

| 不带排序 | 广东页 1–3，各 10 行 | 已有采集试跑 30 行仅 23 个不同 ID，跨页重复 7；不能按页拼接后宣称全量。 |

| `levelSort=1` | 广东页 1、2 各重复两次 | 同一页第 1 页仅 6/10 个 ID 在两次请求中相同，第 2 页仅 4/10 相同；且相邻页有交叉。 |

| `priceSort=1` | 广东第 1 页重复两次 | 两次均为同一组 10 个 ID，但行顺序不同；此样本不能证明其他页稳定。 |

| `checkSort=1` | 广东页 1–3 重复两轮 | 对应页两轮的 ID 集各 10/10 相同，每轮前三页各 30/30 不重复。 |

| `checkSort=1` | 广东页 20、21、140–143 重复两轮 | 同页 ID 集交集分别 10/10、10/10、10/10、10/10、9/10、2/2；第二轮末段 140–143 有 1 个相邻页重复，抽样 52 行仅 51 个不同 ID。 |

因此 `checkSort=1` 比默认排序在样本中稳定得多，但尾段仍有漂移。不能以某个排序参数、单轮分页或简单去重保证没有漏机构。总量也可能在抓取期间变化。

## 暂停与恢复条件

同日另一采集试跑在广东连续 30 页后遇到 11 次 HTTP 429。收到该信息后立即停止一切进一步请求，不以切换代理、多 Agent 并发或轮换地址绕过限流。恢复前先核对官网使用规则、响应 `Retry-After`（如有）及适当等待时间；之后以低速、可中止的分区试验验证。

若允许恢复，优先固定 `areaCode` 到省/市/区及排序值，逐分区记录 `total`、页数、所有页的 ID 集、总量漂移和跨页重复。可试正反排序互补，但只有“所有预期页成功、响应总量稳定、去重后 ID 数等于该分区 `total`、不同分区无异常重叠”同时成立才可把该分区标记完整；无法证明时保留明确缺口，不能发布全量结论。详情接口仅对已确认的唯一 ID 请求，并独立审计详情覆盖率。

## 北京时间约 22:45 的有界单页补测

在先前 429 冷却结束后，单进程、单线程以 10–15 秒间隔，仅补测广东缺失的第 16 页（命令限定 --max-pages 16，已有其他页不重抓）。该次请求没有得到可保存的机构页：HTTP 请求完成并解析出 JSON 业务码 1，非 HTTP 429；采集器当时只在 manifest 记录 `queryOrganizationDataList: business code 1`，未留存响应 `msg`、确切 HTTP 状态或响应哈希，不能确认是参数、服务端暂时故障还是风控。保存页仍为 19/143、190 行、139 个不同平台 ID、51 次重复；第 16 页文件不存在，`complete=false`。目前不再重复请求该 API。

为使后续获准的有界诊断可区分原因，采集器现对 2xx JSON 的非零业务码只在 Git 忽略的 `data/private/mca-institutions-2026-11-18/errors/` 记录请求时刻、端点、参数、HTTP 状态、响应 SHA-256、业务码与最多 160 字符的 `msg`；不记录原始错误响应或个人字段，且不自动重试。此前这次业务码 1 的 `msg` 无法追溯。

## 2026-11-19 自动校时及区级有界验证

两次原时间戳请求在 HTTP 200 下返回业务码 1，错误说明为“请求已过期”。官网首页 HEAD 的 Date 比本机时间中点约快 6–7 秒；保持签名算法、32 位 nonce、请求体和广东第 16 页不变，仅将签名时间戳前移 7000 毫秒的单次探针返回业务码 0、10 行。随后采集器改为以官网 HTTP Date 自动校准签名时间（不硬编码偏移），实际有界重跑成功保存第 16 页。广东已保存 20/143 页、200 行，但仅 145 个不同平台 ID、55 次重复，完整性仍为 false。

番禺区代码 440113000000 的单页试验返回 total=22、每页 10、预计 3 页；只保存第 1 页，不能称该区完整。该页 10 行的 areaCode 均为番禺区本级，不能假设继续按镇街子节点拆分可覆盖全部。本轮不以默认动态 offset 分页继续全省批量采集，后续排序试验必须使用隔离目录与独立完整性核查。
