# 全国养老服务信息平台机构列表完整性核验方法（2026-11-19）

## 范围与判定

本文仅审查本地已保存的官方前端 JS、地区树和列表响应，不发起官网请求，也不修改运行中的采集任务。目标是界定“全国机构列表零遗漏”的证据条件；列表完整、逐家详情完整、当前在营和公开再展示应分别验收。当前不能证明全国列表完整，snapshotVerified 应保持 false。

**当前最小阻断**：广东省级分页已观察到跨页重复；所存前端代码没有暴露按机构唯一 ID 排序、稳定游标或冻结快照，也没有“仅本行政级别直属记录”的精确过滤项。因此单靠收齐页码、递归区县或重复抓两轮，不能证明没有遗漏。

## 递归分区与对账算法

1. 冻结官方地区树：按节点 id/pid/level/sbcode 递归，保存每个父节点的原始响应、哈希、时间和子节点数；检查 ID/代码唯一、无环、父子关系与遍历闭包。完成 maxLevel=3 只能称“已枚举三级范围”，还需逐个查询三级节点的孩子，或取得官方终止层级的明确证据，才能称其为叶节点。无代码节点以及新疆生产建设兵团等特殊根节点单列审计，不凭数字前缀推断归属。
2. 固定每次列表口径：地区代码、筛选项（尤其 ahae0635）、排序、页大小和采集时间窗。逐页保存请求参数、HTTP/业务码、响应哈希、total、current、实际 size、机构 axbe0001 与原始 areaCode。任一缺页、业务错误、429 或总数变化使节点保持未完成；限流后停止站点请求，不通过切换 IP、Agent 或分区绕过。
3. 对每个节点枚举全部预期页，核对页数、末页长度、页内及跨页唯一性、各页 total 一致，并要求去重 ID 数等于稳定 total。允许的请求预算内独立复核一轮，比较页级及全集 ID、总数和时间窗。两轮一致只能说明重复性；没有稳定游标、唯一排序或冻结快照时，仍不能证明零遗漏。
4. 用官方树定义父节点 P 的子节点 C。保存各查询 ID 集 S(P) 与 S(C)，另算直属集合 D(P)：原始 areaCode 等于 P 的 sbcode 的记录。要求 S(P)=D(P) 与所有 S(C) 的并集，各子集包含于父集，兄弟节点无异常交集；父集减去孩子并集必须全部由有证据的直属记录解释。若父级分页不稳且没有精确直属查询，就无法证明 D(P) 穷尽，该节点继续未完成。未知 areaCode、同 ID 多归属或兄弟交集进入隔离复核，不静默去重。
5. 每个官方根节点及其直属残差都通过后，以 axbe0001 对根集合并集去重，核对同一时间窗、相同筛选口径的全国 total，并调查根间交集。历史报告的 39,384 等数字仅供当时口径参考，不能跨时间当作差额基准。详情成功率、字段冲突及公开使用边界另行审计。

## 验收证据与当前状态

每个节点须有机器可读清单：官方节点与父 ID、查询口径、预期/成功页数、total、行数、唯一 ID 数、跨页重复、两轮差异、直属残差、父子子集/兄弟交集、原始响应哈希及失败原因。全国汇总只合并通过验收的节点。只有这些证据均通过，并有稳定分页/快照或等效可核的穷尽机制，才能将列表 snapshotVerified 置 true。
