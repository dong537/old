# MCA 机构列表穷尽分片离线核验（2026-11-19）

本轮只读检查已保存的官网脚本、93 份列表页、32 个一级地区首屏和两份地区树根种子；没有向官网发出新请求，也没有改动运行中的采集器。本文中的数量是**缓存样本**，不能外推为全国机构总量。

## 口径与证据

- 已存官网脚本 `data/private/mca-institutions-2026-11-18/static-js/chunk-3d5896b7.22ca4f71.js` 的 SHA-256 为 `fbacdc322a8ca108c4ed0327113ee9c8d5ab44b56b4f12fd940891ef8bd577c1`。`InstitutionServicesList.getList` 通过 `queryOrganizationDataList` 提交 `current`、`size`、`areaCode`、名称关键词 `axbe0003`、多种属性筛选及 `filterParams`；页面代码没有给出按机构唯一 ID 排序、游标或冻结快照。`tagValue=3` 出现在详情/地图的路由参数，不是本脚本中的列表请求条件。这个结论仅覆盖所存脚本。
- 页面初始 `filterParams` 含 `ahae0635=1`；`FilterPane` 把它标为“仅显示补贴参与机构”，默认勾选。**现有 93 份缓存页的请求参数均未携带 `ahae0635`**，也未携带 `tagValue` 或 `axbe0004`。因此它们与网页默认勾选状态不是同一口径；要搜寻全部公开机构，不能把默认补贴子集的 `total` 与无此筛选的结果混算。缓存行中 `ahae0635=1` 有 837 行、`0` 有 57 行，说明无筛选请求至少观察到两类值。
- 93 页保存 894 行，按 `axbe0001` 去重为 738 个 ID；全部 894 行的列表 `axbe0004=1`、`axbe0004Name=养老机构`。这说明**所存样本**均呈现该类型，不能证明服务端任何未访问页都只含此类，也不能把详情端点同名 `axbe0004` 当同义字段（另见生产就绪审计）。
- 32 个一级地区首屏合计 310 行；其中至少 6 条在原始行上直接挂一级代码，分布于 `220000000000`（1）、`440000000000`（2）、`640000000000`（3）。这只是首屏下界，不是三个地区直属机构的完整数。仅合并市/县子节点必然遗漏这些已见记录。
- 广东无补贴筛选的省级 `total=1422`；先前默认排序 20 页共 200 行只含 145 个不同 ID，`checkSort=1` 的尾段也有跨页重复/轮次漂移。服务端曾把 `size=100` 限为 10。收齐页号或简单去重不能证明全部 ID 已出现；各页 `total` 一致也不能排除动态 offset 的边界交换。证据见 [分页稳定性小样本](./mca-pagination-stability-2026-11-18.md)。
- 地区树 `-1.json` 与 `9a94f430a4604063bb357fca8b616080.json` 的 provenance 是 `cached-json-payload`、`originalHttpBodyAvailable=false`。它们的本地 JSON/哈希不能冒充原始 HTTP 字节的核验。后续新请求保留原文；这两份根种子仍须在不覆盖旧文件的前提下单独重取并对账，或明确保留根来源原文缺失的生产缺口。

## 候选分片是否可证明穷尽

| 方法 | 已有证据 | 当前判定 |
| --- | --- | --- |
| 官方 `areaCode` 树递归 | 父节点查询可含后代；首屏已有省级直属行；三级节点下是否有四级节点待探测 | 可缩小分页漂移影响，但必须保留每级直属残差；仅叶节点拼接不完整 |
| `checkSort`、价格或星级正反排序 | 小区县重抓较稳定，广东尾页仍重复；页面无唯一 ID 次排序 | 可交叉发现新 ID，不能作为稳定快照或零遗漏证明 |
| 名称 `axbe0003` | 页面称“机构名称或关键字”，未证明前缀匹配、分词/大小写规则、互斥划分与空值覆盖 | 不能用首字/拼音枚举未知机构并声称穷尽 |
| 机构属性、收费、补贴、空床筛选 | 部分为多值或随时间变化；`ahae0635=1` 只是默认补贴子集，未见独立的“仅 0”可核全补集 | 可做补充观察，不是已证实互斥且完备的分片 |
| `tagValue=3` 或 `axbe0004=1` | 前者只见于路由；93 个列表请求都没有后者参数 | 不能把路由参数或返回字段臆造为列表筛选 |

## 下一次可执行的验收路径

1. **冻结来源树。** 让现有单线程任务完成三级地区树并审计批次链；独立、限速地重取两份根节点原始 HTTP 响应，与原 JSON 的节点 ID、父子关系、代码和集合逐项比对，保留两版哈希，不覆写旧种子。再运行三级子级探测，记录四级节点和无代码/特殊根节点。
2. **固定一次列表口径。** 为每个节点记录无补贴筛选的请求参数、排序、页长、采集窗口、首尾页和 `total`。按站点共享预算逐页保存原响应及 ID；缺页、业务错误或 429 是中断，不是空集合。把“页码均访问”“页级无重复”“唯一 ID 数等于稳定 total”“第二轮一致”分列验收，不能混成单个 complete。
3. **逐层做直属残差。** 对父节点 P、官方子节点 C 保存完整 ID 集 S(P)、S(C)，并用原始 `areaCode` 找到已观察直属 D(P)。必须核对 S(P) = D(P) ∪ 所有 S(C)、子集包含关系及同级异常交集；**D(P) 本身必须由稳定父级分页、精确直属查询或官方批量原件证明穷尽**。目前没有这种证据，因此仅能累计已观察 ID，不能把根节点 `total`、子级 `total` 之和或重复轮次当作零遗漏证明。
4. **分开验收详情和发布。** 每个最终 ID 两类详情均取到原响应，校验字段语义、资料日期和跨端点冲突；特别不能让详情 `axbe0004` 静默覆盖列表类型。公开再展示的字段许可、个人信息及现时状态独立核验。列表穷尽未证明、详情未齐或字段冲突未解时，`snapshotVerified`、`nationalComplete`、`publishable` 保持 `false`。

可以先用已经两轮保存的北京东城区、河南杞县及广东番禺小分区作为**方法回归样本**，检验代码能否正确识别稳定页、重复、直属和差异；这些小样本通过仍不能外推全国。新增官网试验必须共用当前站点锁、60 秒间隔及滚动小时预算，避免与正在运行的地区树并发。
