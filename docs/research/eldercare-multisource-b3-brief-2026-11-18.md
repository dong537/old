# 九站养老机构信源 B3 并行采集方案（2026-11-18）

状态：采集与离线核验已完成；逐站结果和未覆盖范围见 `eldercare-multisource-b3-2026-11-18.md`。此批未发布网站数据。

## 目标与边界

按用户指定的三家商业目录、两个全国官方入口和四家地方官方平台，查找可公开访问的逐家养老机构信息，形成可复核的私有来源观察与既有目录查漏清单。成功标准是逐站给出入口、访问/robots 结论、实得原件、逐行字段与来源、去重口径、可复算数量及未覆盖范围；不能把检索摘要、目录总数或工商主体数冒充逐家在营机构。此批先采集和清洗，不直接改网站公开数据、部署或付费查询。

## Source of Truth 与数据流

- 权威源为网站自身公开页面、附件或被公开页面调用且允许正常访问的数据接口；商业站内容与官方机构名录独立保存，互不覆盖。每条保留原始 URL、页面/附件标题、取得时间、原文资料日期、原件路径与 SHA-256、解析字段及原文位置。未知值为 null，禁止补零、推定在营或空床。
- 原件和提取结果仅写 `data/private/eldercare-multisource-b3-20261118/<agent-scope>/`；报告写 `docs/research/subagents/eldercare-b3-<scope>.md`。私有数据由既有 `.gitignore` 排除；报告不含电话、个人联系信息或未经核实的逐行商业字段。
- 外部站点 → 原件归档 → 保守字段解析 → 本地候选对账 → 私有报告。既有全国官方分片和全国机构线索只作为比对快照；名称/省市相似只能产生候选，不自动合并或发布。
- 身份键优先来源记录 ID 或源 URL；没有稳定 ID 时用来源 URL、原文名称、行政区域组成观察键。来源观察数、去重 URL 数、名称键数和确认机构数分开统计。

## 并行边界

1. `national`：全国养老服务信息平台 `yanglao.mca.gov.cn`、全国养老机构信息查询 `app.gjzwfw.gov.cn/.../qgyljgxxcx/`；只写 `national/` 与对应报告。
2. `beijing-shanghai`：北京养老服务网 `beijingweilao.cn`、上海市养老服务平台 `shyl.mzj.sh.gov.cn`；只写同名目录与报告。
3. `chongqing-shenzhen`：重庆市民政局 `mzj.cq.gov.cn`、深圳民政在线 `mzj.sz.gov.cn`；只写同名目录与报告。
4. 主线程 `commercial`：养老信息网 `yanglaocn.com`、养老网 `yanglao5.com`、养老机构网 `xyanglao.com`；只写 `commercial/` 与总报告。养老信息网此前已读到针对当前命名客户端的禁止抓取规则，不再直接自动请求源站；可复用已冻结的私有证据，但不能把它算成新正文。

## 访问、安全与失败处理

先查 robots、网站公开入口和访问条款；低频、有限页数探索公开目录和附件。不得绕验证码、登录、403、机器人规则或反爬，不扫描隐藏接口；访问失败保留状态、时间与 URL，不返回伪空名单。外部搜索索引仅用于发现 URL，必须单独标记，不能写成来源正文。每站先取得一个可验证的逐家样本再扩大；若该站只有聚合介绍或 JS 小程序无法正常导出，记录障碍和可人工获取路径。不得重复下载既有相同版本原件。

## 验证与合并门槛

各 agent 对原件 hash、行数、字段映射、分页边界、重复 ID 和缺失项做测试或独立核对；报告写明已查与未查范围。主线程合并前核对跨源同名冲突和现有官方/商业快照，保留逐字段来源；不把候选关系升级为身份确认。采集脚本应可重跑且不覆盖既有原件；公开站点未改变时，无需网站构建，若改公开数据则另做生产构建与浏览器验收。
