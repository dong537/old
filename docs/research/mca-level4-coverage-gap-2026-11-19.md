# MCA 四级地区节点覆盖缺口与最小改造（2026-11-19）

## 结论与证据边界

本轮只读检查现有脚本和本地私有缓存；未请求官网，也未改正在运行的采集器或公开目录。**尚不能断言官网实际存在四级节点，也不能断言已有父级列表必然漏掉四级机构**：三级子节点探测尚未开始，父级 `areaCode` 查询是否对所有四级后代穷尽也未得到证明。若探测出四级节点，现有流水线只会记录缺口，**不会独立查询四级代码的列表页**，因而不能验收全国零遗漏。

2026-11-19 08:03（北京时间）的一次非冻结读数：`area-tree-20261119/responses` 有 104 份响应，含一级 35、二级 344、三级 877 个节点；三级中 745 个有 12 位 `sbcode`、132 个没有。此时运行中 `manifest.json` 仍停在 93 份响应、`treeWalkComplete=false`。这些数字是瞬时**已保存样本**，不是全国最终地区数。`area-level3-probe-20261119/` 尚不存在，**可核四级节点数为未知，不是 0**。无代码三级节点的样本包括辛集市、定州市、北京市经济技术开发区；不能凭名称推造查询代码。

## 当前数据流中的断点

1. `fetch-mca-area-tree.py` 的自动树任务以 `maxLevel=3` 结束；`build-mca-area-seeds.py` 明确拒绝超过三级的节点，将三级的子级状态记为 `child_scope_not_enumerated`。首屏采集器只消费此文件的 `seeds`，且无 `sbcode` 节点进入 `uncodedNodes` 而不被查询。
2. `run-mca-observed-stage-handoff.py` 等**全部三级种子首屏已完成后**才运行 `probe-mca-level3-children.py`。探针可保存三级父节点的子响应、统计 `level4NodeCount`，但后续仍直接进入原种子的 small/large 分页及详情阶段；其状态中的 `level-four-nodes-not-in-area-seeds` 只是报告，不是补采。
3. `collect-mca-area-followup-pages.py::allowed_area_codes` 仅从原三级种子构造后代代码集合。若父级返回四级代码记录，审计会出现 `areaCodeOutsideOfficialSubtree`；这可能是**缺少子级种子导致的误报**，不得自动丢弃该行或将其当作官网错误。
4. `collect-mca-observed-details.py::build_queue` 只合并原三级种子的首屏和后续页。若四级机构已在这些父页出现，ID 可进入详情队列；但这不能证明四级全集。若只出现在四级专属查询，现有队列看不到它。省级首屏已经观察到直属机构，故只拼四级或县级叶子也会漏父级直属记录。

## 最小安全改造顺序

1. **完成并冻结现有任务。** 先让三级树、现有首屏和三级子节点探测完成，逐份验原响应、哈希、父 ID、层级、代码唯一性与批次链。探针终态必须同时给出 `allLevel3ChildrenEnumerated=true` 和实际 `level4NodeCount`；有任何未查父节点、限流或错误就保持未知。
2. **若确有四级节点，建独立的增量种子层。** 从已验三级探针响应派生四级节点、完整官方祖先路径和原响应哈希，另存私有的版本化 overlay，**不覆写**已由首屏 manifest 绑定哈希的三级种子。无代码四级节点单列缺口；不能按行政代码前缀猜。若四级节点下还可能有子级，复用有界子节点探测直到证实叶级或记录下一级缺口。
3. **只查询新增且有码的四级代码。** 为 overlay 单独建首屏和分页缓存，继续用同一站点互斥锁、全站冷却和滚动 60 次/小时账本，串行、每批有上限、429/业务错误立即停止；保存请求参数、原 HTTP 字节、哈希、时间、`total`、每页 ID 和异常，不写网站公开目录。原三级种子的首屏与分页无需重抓。
4. **以来源页为单位合并观察 ID。** 在原详情队列之外按平台 `axbe0001` 合并 overlay 的已观察 ID，保留同一 ID 的每个来源页、时间与哈希；只为缺详情的 ID 增量抓两类详情。详情阶段启动前固定并审计合并队列指纹，不把中途新增页面静默并入正在运行的批次。
5. **单独验收父子与直属残差。** 对父级 P、孩子 C 比较同口径的 `S(P)` 与 `S(C)`，核查原始 `areaCode`、跨页重复、`total` 漂移与父级直属集合。省级已有 6 条一级直挂首屏记录，不能仅以叶节点计数证明覆盖；即使页码全部访问，缺稳定游标/冻结快照时仍保持 `nationalComplete=false`、`snapshotVerified=false`、`publishable=false`。

## 最小测试与运行兼容性

- 探针：零四级、有码/无码四级、跨父重复 ID/代码、非四级越级、坏原文、批次断链、429 冷却及恢复。现有 `tests/test_mca_level3_probe.py` 可延伸，但不可把“已枚举三级子节点”等同“全国完整”。
- overlay：原三级种子与既有缓存哈希保持不变；四级原始路径可追溯；无代码节点不被伪造为可查询；变更 overlay 源哈希须阻断恢复。
- 列表与详情：四级专属 ID 进入增量详情、父子共有 ID 去重并保留两个来源、四级 `areaCode` 不被误判或吞掉、父级直属 ID 保留。测试使用离线响应 fixture，网络请求只由有界执行入口发起。
- 调度：现有 `run-mca-observed-stage-handoff.py` 在四级大于零时仍会继续原范围；引入 overlay 阶段后须明确把四级子级探测／首屏／分页安排在**原范围详情完成之前或作为独立增量队列**，并对版本化源指纹作门禁。严禁两个调度器并发竞逐站点锁。

当前可执行的安全策略仍是继续采集和审计**已观察范围**，并显式展示四级与无代码地区缺口；不得把 `level4NodeCount=0` 的未运行状态当作零遗漏证据。
