# MCA 正式批次与旧试采分组门禁（2026-11-19）

## 目标与边界

正式全国机构目录的字段门禁只评价有现代来源链的首屏、分页与详情。旧试采仍是历史观察，独立审计和计数，但不能因为缺原始 HTTP 字节、旧时点独有 ID 或旧字段值变化而压低现代门禁，也不能补足现代批次缺失的详情。此改动不证明全国零遗漏、不改变在线采集器、限速、业务发布开关或网站展示。

## Source of Truth 与数据流

- 现代来源：`national-area-*` 与 `national-level4-*` 页面、`national-observed-details-*` 与 `national-level4-observed-details-*` 详情，及对应 seed、manifest、queue、连续批次、checkpoint 和原始 HTTP 字节。正式门禁从这些私有文件读取，按现有来源链校验。
- 历史来源：`area-<12位行政码>*` 的旧页面及详情。它们只生成独立的 `historicalLegacy` 诊断摘要；不能进入现代 ID 集合、完整性分母、原文门禁、字段冲突或生产结论。
- 门禁报告在现代文件出现后以现代 cohort 为主；无现代文件时仍可显示旧试采诊断，但所有生产发布标志维持 false。输入文件快照与哈希分别核验，任一分组在审计中漂移均不能伪装为可发布。现代 queue 的 ID 仍须逐项对应现代原始页面；同 ID 的旧详情不参与现代覆盖。

## 失败、验证与回滚

现代页/详情不全、原文缺失、来源链损坏、ID 不一致或审计中变动，继续 fail-closed；历史诊断失败只影响历史分组，不提升现代通过率。先用混合 fixture 复现旧试采误压门禁，再用同 ID 旧详情无法填补现代缺失的 fixture 验证隔离；运行字段门禁定向测试、完整 MCA 离线测试及编译/差异检查。此轮不迁移或覆盖私有原件，回滚仅涉及字段门禁、测试和本方案。

## 实施与验证记录

- 正式与历史文件分别聚合；有现代页面、详情或来源链文件时，主报告只用现代分组，旧试采保留在 `historicalLegacy`。只有旧试采时主报告继续显示其诊断，所有发布标志仍为 `false`。同 ID 旧详情不能补足现代详情。
- 定向回归 `python -m unittest discover -s tests -p test_mca_field_production_gate.py -q`：30 项通过。完整离线 `python -m unittest discover -s tests -p test_mca_*.py -q`：374 项通过。`python -m compileall -q scripts`、`rtk git diff --check` 退出码均为 0。
- 以上均为离线验证，不证明当前全国采集完整或可公开发布。

## 跨分组审计期间的漂移复核

独立复审发现：现代分组审计已经通过后，旧分组扫描期间若现代 status 或其它原件变动，旧实现可继续返回现代 `verified`。现于返回前再次列举现代页面、详情与来源链文件，并逐文件复核**原始文件字节 SHA-256**；文件集合增加、减少或任何文件字节变化，均标记 `input_changed_during_audit`，撤销现代来源批次 `verified`、有效详情计数和所有现代门禁。保留的形状/字段观察只标为漂移前诊断，不代表当前文件快照。该复核仍是有限时点的文件检查，不宣称与运行中采集器形成原子快照。
