# 养老信息网私有归并脚本独立审查（2026-11-18）

## 审查范围与方法

只读审查 `scripts/reconcile-yanglaocn-private.py`、`tests/test_yanglaocn_reconciliation.py`、四批本地搜索 JSON 和 access 下的两份派生 JSON。没有访问源站，没有改动共享脚本、测试、公开目录或旧原件。完整 CLI 写入测试在系统临时目录内复制的最小仓库中执行，临时仓库没有网络依赖，结束后自动清理。

初始 8 项单元测试全部通过，但不足以覆盖以下缺陷。发现项已实时反馈主线程；本报告先保留原始复现与修复要求，最终复审结果在下方单独记录。

## 发现项

### R1：跨观察拼接名称和地域，产生没有单条证据支持的候选（P1）

初始 `merge_observations()` 分别收集所有名称、所有合格省份和城市，顶层名称取排序首项，地域则从其他观察取值。`match_candidates()` 又把所有 `observedNames` 与同一候选省份组合。

真实输入的 `https://www.yanglaocn.com/ylyxx/y29999.html` 同时出现：

- 西北批搜索摘要：“泉和养老康复中心”，天津、天津、静海区。
- 已下载广州详情中的链接文字：“广州市荔湾区中南街综合养老服务中心（颐康中心）”，`link-only`，没有省市证据。

初始归并结果把广州链接名称作为 `institutionName`，却配上天津省市与 `search-snippet-only` 等级。即使存在 `name-conflict` 标记，顶层行和后续名称匹配仍然使用了没有单条来源支撑的组合。

修复要求：代表名称、省市来自同一条优先观察；匹配只使用同一条合格观察携带的 `(name, province, city)`，不能让 `link-only` 名称借用另一观察的地域。保留全部原始观察与冲突。省份冲突时停止合并匹配。

### R2：仅检查输出目录位于 private，不足以保护旧文件及公开目录（P1）

初始 `main()` 只检查 `output.resolve()` 位于 `data/private` 之内，然后对三个固定文件名执行 `write_bytes()`。两个完整 CLI 复现均退出 0：

1. `--output` 指向输入文件所在目录，已有 `summary.json` 内容为 `ORIGINAL-SOURCE-METADATA`；运行后被归并摘要静默覆盖。
2. 在 private 输出目录预放 `summary.json`，使其与临时仓库 `public/data/protected-original.json` 为硬链接；运行后公开路径的原内容 `ORIGINAL-PUBLIC-CONTENT` 也被改写。目录自身的 `resolve()` 无法检测硬链接。

所有复现只影响系统临时目录中的测试文件，未触碰真实项目原件。

修复要求：正常写入仅允许全新或空的专用输出目录；拒绝既有输出文件/链接，使用排他创建防止静默覆写；`--check` 保持只读。至少补齐旧文件/硬链接保护与校验失败不写入的回归测试。

### R3：城市冲突标记被最后一条观察覆盖，结果受输入顺序影响（P2）

对相同 URL、名称、省份生成两条合格搜索观察：`a` 城市深圳，`b` 城市广州；目录同名条目城市广州。`match_candidates()` 对同一目录 ID 合并支持观察时，虽保留两条支持 ID，但反复覆盖 `cityConflict`：

| 观察顺序 | 支持 ID | 初始修正中 `cityConflict` |
| --- | --- | --- |
| `a(深圳), b(广州)` | `a, b` | `false` |
| `b(广州), a(深圳)` | `a, b` | `true` |

修复要求：对冲突标记做单调聚合（例如 OR），并保留冲突观察 ID；不能因另一条城市一致的证据删除已有冲突。

### R4：未匹配名称计数继续跨观察拼接地域，真实结果多算一项（P2）

顶层代表观察修正后，`unmatchedKnownProvinceNameKeys` 仍通过 `for n in c["observedNames"]` 把整组名称与候选省份组合。真实 y29999 最终为天津“泉和养老康复中心”、没有同省精确名称匹配，但广州的 `link-only` 名称也被计为天津未匹配名称。

实际数据复算：旧表达式为 **109** 个 key，按同一合格观察的名称/省份 tuple 应为 **108** 个；唯一差项为 `(天津市, 广州市荔湾区中南街综合养老服务中心(颐康中心))`。

修复要求：该统计与匹配使用相同的观察级证据门槛，避免统计另开一套证据语义。

## 已核对的正确边界

- 输入分为搜索摘要、正文观察和仅链接三级，没有把搜索抓取时间或 URL 日期升级为正文资料日期。
- 已下载广州正文 hash 被重新验证；费用、电话及混合规划床位仍在 `rawObservation` 中保持原观察的空值/限定语义，没有转为已核实机构事实。
- URL 只接受本域两类既有机构详情路径；查询参数和片段被去除，www/apex 仅为明确说明的语法查找键，不声称 HTTP canonical 或去重后的机构实体。
- 候选身份确认、在营与公开资格没有自动升级；没有网络客户端或源站请求逻辑。
- 真实六份输入离线展开为 174 条观察、167 个语法详情 URL；对应 110 个摘要级 URL、56 个仅链接 URL、1 个正文观察 URL。不同 URL 不代表不同机构。
