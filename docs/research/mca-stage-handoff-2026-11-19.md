# 全国平台采集阶段衔接（2026-11-19）

目标：用户要求直接取得官方平台逐家机构数据，且不再申请数据。当前地区树由单线程控制器低频采集；后续在树完整并可验证时，自动进入地区列表首屏采集。此衔接不改变公开网站数据，也不宣称全国完整快照。

Source of Truth：地区树的私有 manifest、逐父节点原始响应和已完成轮次 status；build-mca-area-seeds.py 离线核验这些证据并生成不可发布的地区种子。首屏采集器使用该种子、共享站点锁和滚动小时预算；原始响应、状态仅写 Git 忽略的 data/private/。

运行边界：计划任务每小时只做一次本地预检；树未完成时不访问官网。树完成且最后一轮 status 成功时才运行种子审计与首屏控制器。任何树错误、站点限流、种子冲突或控制器锁冲突都会停止这次运行；下次触发仍须通过完整预检。首屏采集器仅抓每区第 1 页，后续分页与两类详情另行阶段性采集，不把首屏 total 当成已取得数量。

故障与回滚：阶段状态写到私有 batch-runs/stage-handoff.status.json；停止计划任务即可阻止新运行，正在执行的首屏控制器按其 .stop 文件优雅停止。保留原始证据与断点，不覆盖历史 batch status。人工检查任何 phase=running 残留、429 或业务错误后才能续跑。

验证：离线测试覆盖树未完、完成、状态异常；实际触发后检查种子哈希、首屏 batch 状态、站点请求账本、无并发和冷却。即使全部首屏取得，仍不能宣布全国机构列表或详情完整、可公开发布。

### 2026-11-19 根原文再捕获前置门禁

stage handoff 在首次首屏前现已自动编排两份旧根的独立原HTTP再捕获：仅tree完整、最终批次/owned manifest哈希一致且原controller/site锁空闲后执行。最大2次串行请求，原缓存不覆盖；干净预算partial记waiting、下次仅补缺根；漂移/429/源码指纹变化/坏缓存/中断一律blocked，后续定时tick不自动解除。既有complete仅离线重审，不再次请求。详见 [实施方案与状态机](mca-root-recapture-handoff-plan-2026-11-19.md)。

首屏批次天花板从固定200调整为min(9999,max(200,2*seedCount))，依据种子文件真实数量；4000种子对应8000批。它不增加每批20请求或站点60/h限额，不保证无限零进度重试。停止文件：batch-runs/stage-handoff.stop。Windows重入由独立handoff锁保护，第二tick不覆盖running状态。

交付验证：stage handoff 16、root recapture 11、first auto 9、observed handoff 16，共52项离线测试通过；实现任务未发MCA请求、未启动任务、未获取在线tree/site锁、未改任何现场数据。
