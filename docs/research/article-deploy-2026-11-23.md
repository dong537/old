## 目标、范围与验收

将当前本地已验证的全国养老目录、机构详情、四个服务入口和首篇机构文章发布至腾讯云 124.223.86.157/eldercare/，供内部预览。成功标准是线上首页、目录、机构详情、文章及其来源链接可用，静态资源加载正常，站点仍保持 noindex。本轮不修改根站、其他路径、Nginx 配置、数据采集任务或机构原始资料；不宣称当前快照代表实时在营、实时价格或空床。

## 数据、配置与模块边界

- 原始资料与授权文件留在本地受控位置；项目构建脚本将已选资料投影到 public/data/，Next.js 15 使用 NEXT_PUBLIC_ELDERCARE_BASE_PATH=/eldercare 导出 out/。该静态包是本次唯一发布对象，远端不执行采集或构建。
- lib/ 管数据映射和文章读取，app/ 与 components/ 管静态路由和展示，scripts/check-public-output.ts 检查输出隔离；Nginx 只负责读 /var/www/eldercare/current/eldercare/。
- 页面 URL 和资产均带 /eldercare 前缀。文章通过机构 ID 和文章 slug 关联；缺失记录不得用假数据补齐。静态站没有写入 API、登录权限或实时缓存失效；要更新资料须重新构建并发布。
- 当前工作树含大量未提交内容，Git HEAD 不能冒充构建来源。发布包须记录构建时间、工作树状态、包 SHA-256 和文件数，禁止将私有源文件上传。

## 发布数据流与回滚

本地原始资料 → 构建脚本 → 公开投影 → Next 静态导出 → 输出隔离检查 → 带 SHA-256 的版本化归档 → 远端新版本目录 → 原子切换 current。发布前读取旧 current 和首页/其他路径的 HTTP 基线；上传后验证归档、首页、404 和关键页面，方可切换。切换后验证首页、全国目录、机构详情、文章、来源锚点、JSON 与 JS/CSS、404、安全头以及根站基线。失败时只将 current 原子切回旧版本，保留旧目录，不改其他站点。
