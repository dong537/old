## 发现

### 高：公开静态构建可选入私有工商模块

- **位置：** `next.config.mjs:3–5, 15–18`
- **风险：** 私有模式只因 `NODE_ENV !== 'development'` 而拒绝。Next CLI 在启动时保留已设置的 `NODE_ENV`（`node_modules/next/dist/bin/next:55–68`）；所以在 `NODE_ENV=development` 的环境运行生产 `next build` 并设置 `ELDERCARE_PRIVATE_PREVIEW=1` 时，此检查会通过，webpack 别名会改指 `lib/companies-local.ts`。在私有数据已生成时，静态页面可能随公开 `out/` 一起包含工商快照，与“私有模式禁止 production 构建、公开构建不导入工商模块”的契约冲突。
- **建议：** 使用 Next 配置函数的 `phase`，仅在 `PHASE_DEVELOPMENT_SERVER` 允许私有别名；对生产构建阶段无条件拒绝私有标记。发布脚本也应显式设定公开模式，但不能以此替代配置层的硬拒绝。
- **证据边界：** 这是由配置与所用 Next CLI 行为推导的可执行风险；本次没有构建或检查 `out/`，不能声称已观察到实际泄露产物。

### 中：搜索框默认边框对比不足

- **位置：** `app/globals.css:24`
- **风险：** `.field` 的边框 `#B5BAC1` 放在白色输入框背景上，对比约为 **1.95:1**，低于 WCAG 2.2 SC 1.4.11 对必要控件边界的 3:1 最低对比。首页搜索框及目录页的名称、地区控件使用此样式；尚未聚焦时，边界可能难以辨认。
- **建议：** 将控件边框颜色调深到与实际相邻背景至少 3:1；保留现有高对比 `:focus-visible` 提示，并在白色和页面底色两种相邻背景上复核。
- **证据边界：** 对比值按源代码中的颜色计算；未进行浏览器、屏幕或辅助技术验证。

## 目标流程静态核查

- 首页搜索使用带标签的原生 GET 表单；区入口指向列表 URL。目录组件按 `q`、`district`、`page` 查询并生成保留有效筛选的分页链接。
- 列表档案链接将当前列表 URL 编入 `from`；详情返回组件只接受固定目录路径前缀，并在合法时返回该筛选 URL，未见开放重定向。详情使用 `generateStaticParams()` 由目录 ID 生成档案，并设置 `dynamicParams = false`；来源和回列表出口均存在。
- 轻微退化：`app/guangzhou/jigou/page.tsx:16` 的静态 Suspense fallback 展示未筛选的前 20 项，其档案链接未带 `from`。脚本加载/水合失败时从 fallback 打开档案，返回会落到未筛选列表。当前 fallback 同时说明“正在读取筛选条件”，属于短暂加载路径；可考虑让加载状态下的结果不可导航，或水合后再显示链接。
- 公开/本机隔离意图清楚：`components/CompanyInfo.tsx` 通过 `@company-data` 读取；`next.config.mjs` 默认指向公开实现，私有开发预览绑定 `127.0.0.1`。但上一节所述构建阶段判断使此隔离并未被可靠强制。
- 静态预览按 `out/` 路由文件读取、绑定 loopback、返回文件系统错误，并拒绝解析到 `out/` 以外的路径；未发现此脚本读取密钥或访问外网的路径。
