# 养老机构详情 DTO 与页面布局（2026-11-21）

## 目标与边界

面向家属，将现有全国线索和地方官方来源的机构详情按全国养老服务信息平台可见的阅读顺序组织：名称与地区、床位/费用摘要、基本信息、服务信息、机构养老、评价，最后是本站的来源证据与核对路径。成功标准是每个展示值都能追溯当前来源，缺失字段明确显示“本来源未提供”，零值与缺值分开；列表筛选、详情链接和返回路径不变。官网收藏、预约参观、服务申请、电话、地图、图片和评价不得在本站以演示操作或未经核实的内容冒充真实功能。

## 页面证据

2026-11-21 在浏览器打开用户给定的民政部详情页，截图保存于本机临时目录 `mca-detail-reference.png`。可见区块依次为机构头部，床位与四项费用摘要，基本信息/地图，服务信息，机构养老床位和收费标准，用户评价。该单页是布局证据，不代表全国字段均非空、数据有再发布许可或机构仍在营。本站保留自己的来源说明，不复制官网品牌与不具备的交易按钮。
本轮补查官网详情 JS/CSS 模板：机构头部还包含有条件显示的养老消费补贴、功能定位、机构星级与图片轮播；四类费用另有说明字段。桌面模板使用浅金渐变、36px 机构名称、22px 分区标题和 80px 横向内边距。当前浏览器通道不可用，上述尺寸和有条件字段来自模板而非实际渲染截图，故只要求信息顺序与层级对齐，不宣称像素级复刻。

本机私有预览按已观察的原始路径映射独立 DTO：`orgBaseDetail.ahae0021` 为面积，`orgBaseInfo.infoDetail` 为介绍；`orgServiceInfo` 的 `serviceDetail/serviceTeam/serviceTime/serviceRadius/serviceRadiusExplain` 对应服务五项；`yangLaoOrgDetail.ahae2347/ahae0019/ahae2343/ahae2323` 对应总、日托、全托、护理型床位；`hae8List` 的 04/02/01/03 在已观察详情页对应月总、床位、护理、膳食费用；`hae4List` 对应收费项目。代码与标签的对应只以已观察样本为依据，遇到非空冲突保留冲突状态，不推断全国字典恒定。平台标签的逗号、中文逗号和顿号拆分放在 DTO，原始字符串仍保留在证据字段。本机私有预览可显示原件的联系人和电话原值，并附未经本站核验提示；公开构建不纳入这些值。

## Source of Truth 与接口

公开线索仍由 `public/data/qcc-institutions/` 的 11 列投影提供；地方官方来源由 `public/data/national-official/` 的详情与来源清单提供。展示 DTO 仅从已校验的上述记录映射，不读取 `data/private/`，不向官网实时请求。MCA 观察原件的 `publishable=false`，只允许本机私有预览；未来经过覆盖、字段语义、隐私及再展示门禁后，才可作为独立来源接入公开 DTO。

公开 DTO 以字段状态区分 `recorded`、`source_missing`，保存标签、值与来源类型；单位按已确认的字段口径显示，原表行号、资料期、来源名称与哈希继续由原详情页和 manifest 提供。记录值 0 仍为 `recorded`。企查查原表床位、地方官方原表床位和 MCA 平台列示床位不能合并成“当前空床”。月费用、分项收费、服务团队/时间/范围、介绍、地图、图片和评价只在其所属来源实际给出且获准展示时填值；否则显示来源未提供，不以 null 解释为否定事实。原表行号、发布/资料期、来源链接和 SHA 保留原有链路。
公开 DTO 为星级、补贴、功能定位及四类费用说明保留独立缺项状态；只有来源给出且语义与展示权限明确时才填实值。明确的空图片/收费数组显示为“来源记录 0 项”，不得与字段缺失混同；可公开图片提供有效 URL 时展示图片本身，而不只显示数量。
企查查来源线索的原表经度、纬度若同时为有效数值，DTO 可以投影为“原表坐标（未核实）”，原值仅保留在 DTO 与来源证据中，页面暂不显示地图点位或导航；空白、越界和非数字保持缺失。详情抬头保留机构类型、标签、评分及联系字段的缺项槽位，不把缺项解释为不存在；原表明确空数组与来源缺项须分开。广东省仅有名称和来源的记录沿用详情外观，但继续称“来源记录”，不得因布局一致升级为已登记养老机构。

广东省仅名称来源条目使用同一详情 DTO 与栏目顺序；原文证据类型、发布日期、资料期和状态提示保留在来源区，不把“官方名录”误映射成设施类型，也不从名称推断地址、床位、收费、服务或评价。详情抬头显著标为“待核线索”，同名与登记主体候选仍在栏目之后。

## 页面模块与失败模式

`lib/institution-detail-dto.ts` 只负责来源记录到视图字段的映射；共享详情片段负责按分区呈现，不判断真实性。现有详情页继续拥有加载、错误、候选关联与来源核对。移动端单列，桌面正文全宽，页内目录置于正文之后；核对提示放在评价后以免挤压资料栏目。长文本、零床位和空字段需可读，不做不可证实的地图定位。若 JSON 读取或身份绑定失败，保留现有错误与重试，不回落为零或另一条同名记录。

## 验证与回滚

为两类真实来源建立 DTO 行为测试，覆盖有值、null、零值、不同床位口径与来源日期；运行类型检查、测试、静态构建及公开隔离扫描。浏览器抽样真实南京记录和全国线索详情，检查 320/375/768/1440px、200% 缩放、来源出口、返回筛选、控制台与横向溢出。仅改 DTO/页面组件即可回滚，不触动私有采集或原件。
