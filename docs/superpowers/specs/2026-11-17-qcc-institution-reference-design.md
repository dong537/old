# 全国养老机构信息表本地接入方案（2026-11-17）

## 目标与边界

家属在本地静态站按省、市和名称查看用户提供的《养老机构信息.xlsx》逐行线索，并能核对来源行、地区、地址及原表床位数。成功标准是 41,955 条原表行不丢失、不悄悄合并，公开投影可重建，页面清楚区分企查查来源线索、官方来源观察和登记主体候选。现阶段不部署，不称全国全量、当前在营、实时空床或机构与登记主体已核实关联。

## 原件、许可与质量审计

用户说明原件来自企查查，并确认逐家字段有公开展示授权；授权文件及原始下载页尚未归档。本地原件固定在 Git 忽略的 data/private/qcc-institution-reference/，SHA-256 为 6bc157e2695965ed8b1c85e82f6f8b7fa7d13102149f9f1512e9863b2489fd81，4,691,840 字节。工作簿元数据创建于 2024-10-11，但不能用此推断逐家资料截止日；本站记录 2026-11-17 本地接收日期并把资料时点标为未知。原表共 41,955 行、11 列。

原表行政区划代码前缀与“地区”列在 41,955 行均一致。后加的“省份”列在 1,311 行为空，并在 7,086 行与行政区划代码的省级前缀冲突；“城市、区县、经纬度”列因此不作为展示分组或地理定位的权威。公开省份从原表行政区划代码和“地区”交叉验证后得出；66 前缀的兵团行归入新疆的独立兵团分组。地市仅从原表“地区”作保守解析，解析不出时标“地市未标”，不按地址猜测。原表 600 行地址为空，页面展示未知。原表床位数均可读为非负整数，其中 809 行为 0，0 不能变成未知，最大值 5,935 不自动修正。

统一社会信用代码不作为机构唯一 ID：原表 549 行为全零占位、19 行为空。101 行原表仅含小写字母，转为大写后均通过 18 位校验；最终仅公开通过校验的 39,360 行代码，另有 2,027 行格式或校验不通过，仅显示代码状态，不公开错误原值。完全相同的重复行额外 6 行，同省同名额外 98 行，同名同址额外 16 行；全部保留来源行号，不把行数等同于独立机构数。

原表地址列除 600 行为空外，还有 604 行含手机号、座机或邮箱，其中 600 行仅为号码、4 行混合地址与号码；另有 127 行地址字段与机构名称完全相同，属于不可定位的占位。公开投影将后两类整字段置 null，不做截取或猜测；公开地址 null 共 1,331 行。页面统一称“暂无可公开地址”，并把其他地址标为“原表地址字段（未核实）”，不能把遮蔽行说成“原表未提供”或提供导航承诺。

## Source of Truth、模块与接口

原 XLSX 是唯一输入；锁定文件 SHA、字节数、表头、行数及行序的清单是导入契约。离线 Python 导入器验证每行名称、地区与代码前缀一致性、床位和可公开字段，按来源行号生成稳定 ID；显式 check 模式只读对比全部公开文件。任何输入漂移、未归类地区、非法床位或索引/分块不一致都失败，不返回空集合冒充成功。

公开投影置于 public/data/qcc-institutions/，由一个 manifest、按省市索引和最多 100 行的详情块组成。manifest 仅列 31 省级分组、城市分组、行数、快照 ID、接收日、来源说明、文件 SHA。索引项仅含 ID、来源行号、名称、原表地区、地址、床位及分块名；详情另含通过校验的统一社会信用代码或空值、代码状态。原 XLSX、错误代码原值、经纬度及有冲突的省市区派生列不得进入 public/out。

新页面为 /quanguo/cankao/ 和 /quanguo/cankao/detail/：首次进入先选择省、市，再按名称、地址或原表地区检索；详情可回到原筛选，并展示资料时点未知、来源行、来源文件哈希与“仅供核对”的边界。对官方逐名来源的同省同名关联只标“名称相同的来源候选”，链接到双方站内来源记录，不代表同一机构或在营；原始 XLSX 保持私有，来源行号供资料复核。

候选关联由独立离线生成器读取三份已发布的最小投影：本表 41,955 行索引、跨省官方来源索引和广东官方来源 JSON。只以同省且原文名称完全一致匹配，不使用地址、床位或信用代码推定身份；匹配到多行全部保留。独立 public/data/qcc-institution-links/ 快照固定这三份输入快照 ID，按本表 375 个省市组各输出一个 links.v1.json（无匹配也输出空数组）。每条关联包含线索 ID 和官方候选的来源类型、记录 ID、省市、来源标题；客户端校验三份快照一致后才展示，失败时给可见恢复提示，不把空结果说成“无官方机构”。生成器的 check 模式重算全部关联并逐文件比较；公开扫描验证链接目标、ID、覆盖与快照一致。原有三个数据口径与 ID 不变。

数据流为用户授权 XLSX → 私有冻结原件 → 离线校验和最小公开投影 → 静态 JSON → 浏览器按地区延迟加载。URL 承载地区、搜索词和页码；无运行时写入、权限或虚构预约。公开扫描器精确白名单校验文件、字段、行数和敏感值。现有官方目录、广东目录和全国登记主体候选库维持原 ID、路由与口径，三者不能相加为机构总数。

## 错误、回滚与验收

导入前做负例测试，覆盖原件哈希、表头、行数、地区冲突、代码占位、零床位、重复来源行、缺地址及跨块/跨地区引用；构建扫描证明私有 XLSX 和被排除字段没有外泄。运行 Python 行为测试、TypeScript 测试、类型检查、静态构建、公开隔离扫描，并在真实浏览器走省市筛选、检索、详情、返回、空结果及窄屏。只交付本地静态产物；回滚为移除新路由和新投影，既有目录不变。正式部署前仍需归档用户所述公开展示授权依据、确认纠错联系人及更新责任。

## 登记主体代码候选关联扩展（2026-11-17）

目标：让家属在机构线索详情看到统一社会信用代码相同的登记主体候选，仅供进一步核对。输入只读既有三份公开投影：`qcc-institutions` 线索清单、索引及详情分块，`qcc-national` 登记主体清单、索引及详情分块，`qcc` 广东主体索引及详情分块。三个原始投影及各自 ID 不变；登记主体行数不称为养老机构数。

离线生成器验证输入快照、分块/索引对应、信用代码格式及校验位，按代码精确查找。仅当线索与唯一工商记录的省份相同，且两侧代码均有效时发布关联；重复工商代码不自动选一，跨省命中只进入计数审计，不进入公开链接。名称相异仍可显示“代码相同”，但不得推定是同一场所或运营关系。同一登记主体可对应多条线索，关联线索数不能称为登记主体数或独立机构数。广东省工商投影的省份固定为广东省，其余以跨省工商索引的省份为准。

新增 `public/data/qcc-institution-registry-links/`：manifest 绑定三份输入快照、线索行数、唯一代码命中/同省发布/跨省审计/歧义排除数及地区数；按线索清单每个省市输出一个 `links.v1.json`（无匹配也为空）。每条只含线索 ID 和工商目标类型、ID、省市路由、名称与公开城市；不复制信用代码、联系人或经营字段。`--check` 重算并逐字节比较文件集合和内容；测试校验真实目标、代码、地区、路由与计数。浏览器在核心线索详情完成后独立加载该关联及既有官方同名候选，各区具有加载、失败重试、空结果状态；关联文件失败不遮蔽详情。撤回时移除该独立投影、加载器和候选区即可。
