# 跨省登记主体候选目录设计（2026-11-16）

## 目标与边界

家属和研究者可在现有静态站按省、市、名称、主体类型与登记状态检索用户提供的企查查导出快照，查看逐条登记字段和来源。成功标准是 25 份原件的 141,364 行均可追溯、不会因去重丢失；广东既有 6,777 条主体库和官方广州/广东目录保持原口径；首屏不下载全国明细；公开产物无原始联系方式或 XLSX。

这批文件覆盖广东以外 30 个省级地区，属于“养老服务”行业宽口径登记主体候选，不是备案养老机构名录，也不证明当前营业、机构运营关系或全国完整覆盖。页面不得把 141,364 称为养老机构数。保留现有广东主体库入口，不把两批不同快照强行合并计数。预约、认领、评分、实时空床、付费和后台不在本轮范围。用户已确认这 25 份导出的逐家登记字段在公开展示授权内。

## 数据权威、模型与处理

源目录为 C:/Users/Lenovo/Desktop/search/example。25 份 XLSX 是本轮原件，离线导入按每份 SHA-256、37 列标题、工作表、原始行号、各文件行数和合计行数核验；原件不进入 public、out 或 Git。企查查快照仅对其导出时登记字段负责；官方民政等来源仍是机构/设施事实的权威来源。缺失、未知、零和无效代码分别保留，不将登记状态等同服务状态。

公开 CandidateRecord 有稳定 ID、名称、省/市/区、主体类型、登记状态、统一社会信用代码及校验结果、现有广东投影已审阅的登记详情字段、sourceId 和 rowNumber。SourceFile 有文件名、SHA-256、导出日、记录数；manifest 有 schemaVersion=1、snapshotId、总原始行数、按省市计数及允许读取的相对索引路径。非占位代码在本批源内唯一。缺码/异常代码以来源行建立 ID，不能按同名合并。本轮只有一组名称+代码完全重复，两个来源行均保留，避免吞掉来源观察。

离线投影只输出已审阅的登记字段。原表手机号、更多电话、邮箱、企业简介、网址和邮编不映射；名称、地址、经营范围等自由文本若含手机号/邮箱则按字段整体遮蔽并记数。导入器生成每文件哈希与行数审计、30 省与 320 个省市组合计数、缺码/异常码/重复组及脱敏报告；3 条城市占位值落入“城市未提供”组。出现未预期标题、文件增减、总数或省份漂移时失败，不自动发布。静态产物扫描对全国 manifest、城市索引和详情块逐字段白名单校验，禁止 XLSX/CSV 与联系信息进入公开目录。

## 模块与接口

新增离线导入器负责 XLSX 校验、投影、分片和审计；不改现有单文件广东导入器。公开数据路径为 /data/qcc-national/manifest.v1.json 与 manifest 所列省市索引，详情约 100 条一块；URL 中的地区 slug 和 chunk 必须属于 manifest 白名单，不能拼接任意路径。全部 JSON 带同一 snapshotId，读取时不一致则显示错误与重试。城市索引仅含检索必需字段；用户选城市后才加载。

新增 /quanguo/zhuti/ 列表和 /quanguo/zhuti/detail/ 详情，沿用现有站点外壳、中文文案与响应式组件。列表先读轻量 manifest，选定省市后才读该城市索引；筛选、分页与返回状态用 province/city/q/type/status/page URL 参数。城市缺失者在该省“城市未提供”组中保留。详情凭省市和稳定 ID 读取城市索引、再读所属详情块，显示来源文件、行号、哈希、导出日、缺失/代码校验和登记状态警示。非法参数、无结果、文件加载失败、分块不一致均有可见恢复出口。广东入口链接到现有 /guangdong/zhuti/，不搬迁旧 ID 或破坏旧链接。全站搜索在新路由保留地区筛选并转回新目录。

官方来源候选关联只允许同省、同市、规范化后同名，并标为“名称匹配候选，运营关系未核实”；匹配不自动成为机构。当前公开官方来源只有广东 781 条，而本批没有广东行，因此本批与现有官方来源的匹配数为零；界面不得虚构关联。广东既有同城同名候选关系保持原状。未来导入其他省份官方名录时才可重新计算对应关联。

## 数据流、失败与验收

本地 XLSX → 私有离线审计/投影 → 严格公开 JSON → Next.js 静态构建 → /eldercare/ 静态托管 → 浏览器按需读取 manifest/城市索引/详情块。无运行时企查查 API、Node 常驻服务或假实时状态。页面主任务为选择地区、筛选候选、查看登记事实与来源、返回同一筛选；使用原生 link、form、select 与 button，支持键盘和移动端。noindex 保持原站设置。

测试覆盖原件数量/标题/哈希漂移、缺码与错误码、重复与来源行、自由文本联系方式遮蔽、公开白名单、地区分片与快照一致性、搜索/分页/URL、详情/返回、HTTP 失败与重试。运行项目现有 npm run verify:release，浏览器检查首次访问、所选地区、首/中/末记录、错误恢复、320/375/768/1024/1440px、200% 缩放及 /eldercare 前缀。任何数据漂移、泄漏、构建或浏览器关键路径失败均阻断发布；线上回滚继续使用现有版本化静态目录切换。

## 待办风险

原表只提供登记快照，不提供备案床位、收费、当前在营、服务质量或家属可预约性。不能从企业名称或经营范围推断这些事实。全国原始表有 2,161 条代码为 -，另 9 条代码格式或校验异常，均需在公开页明确而不能补造。更新批次必须重新审计来源差异、数据授权、地区覆盖和公开投影后发布新 snapshot。
