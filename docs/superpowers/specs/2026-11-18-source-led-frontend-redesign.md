# 养老信源公开前台改版设计契约（2026-11-18）

## 目标和验收

用户为替家人查询养老机构的访客。主要路径：选地区和输入名称／地址 → 查看机构线索或广州官方名单 → 打开档案 → 核对来源、资料期和可联系信息 → 回到原筛选。首屏必须能开始查找；列表要让用户快速判断记录是什么、来自哪里、下一步去哪核实。公开页面不能暗示本站拥有当前价格、空床、在营状态或完整全国名录。

本轮覆盖共享页头、全国入口、广州入口、广州机构目录和档案、全国机构线索与官方来源目录的共用视觉结构，以及服务记录和指南的公共样式。保留现有数据管线、静态导出、公开路由、隐私规则、搜索参数及内容口径；不实现账户、预约、机构入驻、实时地图、商家排序或新数据采集。独立 prototype、私有预览和运营后台不在范围内。

## 调研证据与采用理由

2026-11-18 对养老信息网广州频道原站 HTML/CSS 的只读核对，见到城市导航、图文导流、地区和条件搜索、区级机构卡及资讯；其列表当时触发安全验证。2026-11-19 补看移动频道及列表：独立手机版有搜索、城市、筛选及机构卡，自动留资弹窗遮挡内容；详情未核。采用地区直达和可扫读卡片，不采用留资弹窗、商家入口、无法支撑的价格和固定宽度。对全国养老服务信息平台首页的桌面截图，见到地区＋关键词首屏搜索、热点服务、服务查询、在线办理及分类地图；地图内容未完整载入。移动首页仍缩放桌面布局，列表／详情未核。采用搜索优先及服务分类，不采用庞大政务导航、浮动宣传条与空地图。移动证据见 docs/research/subagents/two-site-mobile-layout-2026-11-19.md，来源边界见 docs/research/2026-11-18-two-site-layout-redesign-proposal.md。

## 页面结构与任务路径

方案甲“城市入口＋来源核查工作台”作为实施基线；方案乙“直接以全国列表为首页”过于弱化广州已核官方名单，方案丙“门户入口铺满首屏”会推高未开放能力。方案甲的变化限定在信息架构和视觉层，不把不同数据集归并。

桌面：

    品牌 | 找机构 | 官方来源 | 广州服务记录 | 长护险指南 | 来源说明
    所在地区 [省市／广州]  搜索名称或地址 [__________________] [查找]
    广州官方名单入口 | 全国机构线索入口（标明不同证据级别）
    按地区进入 → 结果范围/资料来源 → 可用筛选 → 结果卡列表
    档案抬头（名称、地区、地址、联系）→ 可用事实 → 逐项来源/资料期 → 核对建议

手机：品牌、主菜单按钮及首屏搜索完整可见；地区与关键词纵向排列。目录保留范围标题、结果数和“筛选”入口，筛选面板展开后无需横向滚动；机构卡逐行展示关键事实。无浏览器横向溢出，主操作不被底栏或浮层遮挡。

首页首屏只保留一条主路径：“选地区并查找”。官方名单与全国线索作为明确分开的入口，不用同一个数字合计。目录先显示来源性质与范围，再提供有效筛选；资料限制简写在结果附近，完整方法延伸至来源说明。档案优先展示名称、地址、能公开的联系方式和实际存在的字段；无数据的次级模块不占大段篇幅。对比功能仍保留广州目录当前最多三家的筛选／回列表语义，不改变现有数据算法。

## 保留／替换／删除

- 保留：品牌名称暂名、既有路由与静态导出、广州 q/district/page/advanceFee/deposit/membershipFee/compare、全国 province/city/q/page、详情 from、来源链接、归档日期、未知与零的区分、隐私遮蔽和真实错误提示。
- 替换：三层页头及重复搜索、首页渐变卡和三列概念卡、广州首页五项空值统计、目录大块筛选和六项未知值矩阵、档案长串空区块；统一为搜索优先入口、紧凑可用筛选、内容随来源变化的卡片和证据就近展示。
- 删除：访客页的禁用后台／认领／预约按钮、没有对应数据的排行与筛选控件、造成误导的“未知即无”视觉暗示。页面说明保留功能未开放的必要事实，但不作为首屏操作。

## 视觉方向与组件

第一轮方向：白色内容面＋冷灰背景，深青绿作为操作色，暖橙只标注核对提示；不复制任一参考站点的图、轮播或品牌。内容上限 1180px，正文不小于 15px，表单和主要触控目标不小于 44px。中文使用本地系统字体族，数字采用等宽数字排版；不引入网络字体。以“来源行”作为识别元素：结果卡底部用细分隔带列出来源类别、资料期与核对出口，而非装饰徽章。

第二轮自审：移除无法解释信息关系的 KPI 卡、宣传式插画和固定大图；搜索与结果之间不再重复冗长介绍。旧站图像、价格字段、地图与操作没有可信数据时不出现。页头只保留真实可用的导航；桌面可见两条主要目录入口，手机收为清晰菜单。

组件边界：SiteHeader 仅编排站点导航和轻量搜索；首页选择地区与数据入口；目录组件保持各自数据加载与查询逻辑，通过一致的搜索表单、结果摘要及来源样式呈现；详情组件负责该来源自身字段，不跨数据集补齐。页面路由负责选择来源和静态入口；lib 中现有搜索、数据解析、授权和 URL 规则继续是 Source of Truth。

## 状态、极值和验证

必测 initial、loading、empty、invalid、error、disabled 和恢复；写入／权限／pending 状态不适用，因为本轮只有公开只读页面。样本含长中文机构名、长地址、无电话、未知床位、数字 0、同名记录、失效地区参数和空结果。验证 320/375/768/1024/1440px 与 200% 缩放、Tab/Enter/焦点恢复、主导航和筛选、分页、详情来源及返回原查询；检查无遮挡、溢出和 console/runtime error。通过 TypeScript、现有相关测试与静态构建，并以真实浏览器完成访客路径自测。外部站点移动布局证据缺口与浏览器工具失败须在验收记录中保留。
