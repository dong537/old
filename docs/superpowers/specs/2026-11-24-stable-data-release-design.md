# 静态数据增量发布提速设计（2026-11-24）

## 目标与边界

面向维护全国养老机构目录的站点所有者。数据更新后仍完整构建、扫描并校验静态站，但部署只重写确实受影响的页面和数据文件；保持原子切换与回滚。基线部署 `e8a2817` 的导出有 44,635 个文件，`rsync` 判定 21,217 个文件变化，仅发送 34,373,058 字节，却耗时约 33 分 38 秒；随后全树 SHA 校验约 2 分 52 秒。成功标准：相同代码与数据的两次构建不再因随机 Build ID 导致全站 HTML/TXT 变化；数据更新时变化文件数与受影响内容相关；旧标签页不会把旧目录清单和新索引混用。完整构建、完整清单、发布前校验及预览站 `noindex` 保留。

本次不引入后台数据库、不绕开授权与审核、不以只上传新增 JSON 代替受影响 HTML，也不降低服务器端完整性校验。

## 方案比较与选择

1. **代码版本稳定 Build ID（采用）**：由运行时代码、配置、依赖锁和部署前缀生成确定性 ID；机构数据与文章正文不参与。代码变化仍产生新 ID，数据独立变化不再使每个页面仅因构建标识改变。需处理旧标签页跨版本目录缓存。
2. **只加 `rsync -z`**：当前 literal 数据仅 22.47 MB，传输字节不是主要瓶颈；压缩不能减少 21,217 个文件处理，暂不采用。
3. **按 manifest 差量打包**：可减少全树比对，但若 Build ID 随机仍要处理两万多个页面，还增加删除与校验路径。先解决内容变化源，之后按实测决定是否需要。

## Source of Truth 与模块边界

Git 中的 `app/`、`components/`、`lib/`、Next/CSS/TypeScript 配置、依赖锁及部署前缀共同决定代码版本；`content/`、`data/`、`public/data/` 为资料输入或投影，其变化通过完整构建反映在对应静态产物中，不改变代码版本。哈希算法按规范化相对路径排序，逐文件读取字节并带路径边界，找不到必需输入时失败；不得根据 Git 提交 SHA、构建时间或工作目录名生成 ID。

`next.config.mjs` 只调用构建 ID 计算模块，不负责资料解析。机构目录的服务端页面继续从 `mcaCatalogLoader` 取得 manifest；客户端从固定 URL 读取同一发布版本的 index 并验证 `snapshotId`。发现旧 manifest 与新 index 不一致时，仅尝试一次完整页面刷新以清空旧 Next 预取状态；仍不一致时展示明确错误与手动重试，不循环刷新，也不把不匹配数据当成功。其他网络、格式错误维持原错误反馈。

现有发布链路：Git/公开资料 → 数据投影 → Next 静态构建 → 公开扫描/逐文件 SHA 清单 → GitHub artifact → 服务器候选版本 rsync → 全树 SHA 校验 → 原子切换。候选与线上版本完整隔离，故不需要数据库迁移；新发布失败则保持或回滚前一版本。

## 验证、发布与回滚

测试构建 ID 对相同输入稳定、资料文件变化不改变 ID、代码/依赖/部署前缀变化改变 ID。先取得同输入两次隔离构建的差异基线，再比较修复后的导出：HTML/TXT 不得因构建 ID 产生全站变化；变动数据样本不得使无关页面改写。对旧 manifest + 新 index 注入跨发布浏览器场景，验证限次刷新、恢复和持续错误态。执行 `typecheck`、行为测试、完整静态构建及公开扫描；上线后核对首页、目录、详情、文章、`release.txt` 与 `rsync --stats`。若变动文件数仍接近全站或旧标签页出现不一致，停止切换或回滚原子版本，并保留证据后再改方案。

## 本机复现与修复验证

- 同一提交和输入的原始构建两次均导出 28,813 文件；Build ID 分别为 `BGBS147mq3PLhf8e9OCjB` 与 `HerDyC81SE84yxoeXHYKS`。10,608 个 HTML 和 10,606 个 TXT 全部含各自的随机 ID，故这 21,214 个页面文件全部变化；均匀抽样 201 个页面，替换 ID 后无其他字节差异。
- 修复后对同一代码和资料连续两次完整构建，Build ID 均为 `eldercare-0ad0cd7162fcb1f63b0d9fda`；按路径均匀抽样 201/21,214 个 HTML/TXT 文件，两次 SHA-256 完全相同。两次构建均通过 28,813 文件的公开隔离扫描。完整的逐文件部署差异仍以 CI 的 `rsync --stats` 为准。
- 本机浏览器从正常目录（6,520 个平台 ID）切换为旧页面 manifest/新索引快照不一致：自动刷新一次后显示“目录清单与机构索引属于不同发布版本”及“刷新页面”按钮；手动刷新仍不一致时不循环；恢复索引原字节并刷新后目录正常加载。浏览器临时修改的 `out` 索引已按 SHA-256 对比恢复。
- 独立审查后将两个实际投影生成器 `scripts/build-data.ts`、`scripts/build-service-data.ts` 也纳入代码 Build ID；更改生成逻辑不再错误地保留旧 ID。
