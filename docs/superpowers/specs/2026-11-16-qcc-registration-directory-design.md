# 广东养老相关登记主体目录设计（2026-11-16）

## 目标、范围与验收

家属可在现有 /eldercare/ 站点单独检索企查查高级搜索导出的广东登记主体候选；原省级官方来源目录继续作为机构/设施线索，不把登记主体行数计为养老机构数。导出为宽口径搜索结果，存在与养老服务关联未核实的记录；页面不逐家背书其养老属性。在同城同名的官方来源详情显示一个或多个“登记主体候选”链接，明确运营关系未核实。用户已确认拥有逐家登记字段公开展示授权；公开投影不含导出的手机、其他电话、邮箱或企业简介。首版不开放预约、认领、联系方式、质量评分、当前在营承诺和全量机构覆盖承诺。

成功标准：6,777 条原始主体均可在独立目录检索，21 市可筛选；公开详情可追到来源文件哈希、工作表与行号；157 个官方来源名称键可显示 158 个候选主体引用，允许一对多；广州 235 档案、原 781 条来源和原站不回退。缺失、注销、无效代码与候选关系可见；公开产物不含联系方式和私有原件。

## Source of Truth 与域模型

原件为 data/private/guangdong-eldercare-source/research-batch29-qcc-export-20261116 下 SHA-256 为 e573e8072e65385b48185e5645fffc0ce297a2c28aeae11ed5272ac4f926e480 的 XLSX。它是 2026-11-16 文件名所示导出快照，不是企业或服务实时状态。民政等官方原件仍负责机构名单事实；企查查记录只负责导出时的登记主体字段；查企GO旧表继续独立留存，按统一信用代码和字段来源对照，不覆盖。用户提供的另一份养老机构 XLSX 仍只作查漏线索。

RegisteredSubject 有独立稳定 ID、原始行号、城市、名称、主体类型、登记状态、统一信用代码（可空/校验状态）、可用登记字段、字段原值和快照日期；缺失为 null，不补零。SourceSubjectCandidateLink 只含官方来源记录 ID、主体 ID 与关联规则“同城同名候选”，不声明运营关系。导出中的“企业规模”不作人员规模；事业单位不套企业工商字段。重复名称、不同代码保留不同主体，负面登记状态显著显示。

## 模块、接口与页面

离线投影器验证原件哈希、37列标题、6,777行和21市，重置错误的 XLSX A1 维度，检查代码格式/校验位、空值、重复 ID、字段白名单和联系信息排除。输出版本化最小索引、按约100条分块的详细 JSON 和独立的候选关联映射；不将原 XLSX、邮件、电话或内部路径复制到 public。所有新 JSON 有 schemaVersion、snapshotId、导出日期、记录数，来源更新需重新审阅差异并发布新版本。

新增 /guangdong/zhuti/ 列表和 /guangdong/zhuti/detail/?id=... 详情；列表按名称、城市、主体类型、登记状态检索和分页，参数 q/city/type/status/page 进入 URL，非法参数显示可恢复提示。详情按主体 ID 加载对应分块，显示登记事实、来源、日期、缺失说明及返回列表；无效 ID 给可见错误和列表出口。现有 /guangdong/jigou/[id]/ 仅在映射存在时增加候选主体模块，支持一对多及返回。现有广州、服务、规则页和导航风格沿用；新增导航使用“登记主体”而非“养老机构”。中文文案按现有站点路径实现。

## 数据流、权限、失败与发布

本机 XLSX → 私有离线解析/人工审阅 → 公开字段投影 → Next 静态构建 → 版本化 Nginx /eldercare/ → 浏览器按需获取索引和分块。无运行时企查查或查企GO API、账号、写入或动态 Node 服务。公开输出扫描仅对精确命名的 QCC 投影路径应用字段白名单和敏感值检查，其他文件继续保留既有工商泄漏禁令；不得简单关闭扫描器。发布站继续 noindex，待域名、纠错与更新责任具备再另行开放索引。

原件哈希/标题/行数漂移、联系字段进入投影、错误的候选关联、分块缺失、构建或浏览器失败均阻止发布。线上如故障，将 /var/www/eldercare/current 指回上一版本；不改官方来源或私有归档。测试覆盖投影、字段映射、代码/状态/缺失、一对多、检索分页、静态输出隔离；浏览器验证 320/375/768/1024/1440px、键盘、空结果、详情返回和来源说明。上线核对目录、样本详情、JSON、原省级/广州页、根站、旁站和响应头。

## 仍需人工审阅的边界

6,777 是宽口径主体搜索结果，只有 3,156 行国标行业大类为社会工作；92 行缺代码、2 个格式合规代码未通过校验位。与现有官方来源严格同城同名 353 条，其中已发布来源名称键157个，对应158个主体行；一组名称对应两个个体代码。关系只可标候选，不自动认作运营主体。查企GO 25字段中，企查查14项可直接对照、4项需保留原值后映射、7项缺失或不可替代；来源与字段差异保留，不能以“绝对可信”推断全字段完备或机构当前营业。

## 发布时补充决策

实际宽口径结果中存在名称无法说明养老关联的记录，因此公开标题使用“广东登记主体候选库”，并在首屏明确未逐家核实养老关联。上线浏览器曾因 1.8 MB 未压缩索引经代理传输中断而无法进入检索；为保持静态数据与现有查询接口，仅在 /eldercare/ 的 Nginx location 启用 JSON gzip，响应体约缩至 260 KB。该服务端传输设置保留原 snippet 备份，须经 nginx -t、在线 Content-Encoding、主体检索和来源详情浏览器复核；无需引入常驻应用服务。详见 docs/verification.md。
