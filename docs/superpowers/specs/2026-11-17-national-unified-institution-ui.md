# 全国机构目录统一界面（2026-11-17）

## 目标与范围

家属从首页和主导航进入同一个全国机构线索目录，按省市检索、打开档案、核对官方来源和登记主体候选，再返回原筛选。广州档案是交互和视觉结构参照：面包屑、页内目录、概况、证据分区、右侧核对入口、来源与联系建议。广东不再作为独立的一级导航目的地；原广州、广东路径保留，保证已分享链接可访问。静态导出继续使用现有 Next.js 与 `/eldercare` basePath。

这次不将不同来源行自动合并为一所机构，不虚构电话、价格、空床、预约、等级或运营关系，不把全国登记主体候选当作养老机构。主目标是统一用户任务和页面结构，不重写历史数据及主体快照。

## Source of Truth 与页面路径

- `public/data/qcc-institutions/` 的 41,955 行是全国查找线索，入口为 `/quanguo/cankao/`，详情保持查询参数 `province/city/id/from`，以免静态生成 41,955 个动态页。
- `public/data/national-official/` 的 7,719 行与 `public/data/guangdong-source-records.v1.json` 的 781 行是不同口径的官方来源观察。全国官方来源入口 `/quanguo/laiyuan/` 按省市选择，广东记录仍可指向原 `/guangdong/jigou/[id]/` 详情。两组记录不相加为去重机构数。
- `public/data/qcc-national/` 和 `public/data/qcc/` 是登记主体候选，保持独立。机构线索详情使用既有同省同码与同省同名候选快照；页面标识为“待核候选”，不能写成运营方。
- 广州 235 条官方档案由 `lib/catalog` 提供，仅其真实字段可以显示电话、预收费与备案床位。全国线索及其他官方记录不从广州档案借字段。

## 交互与模块

首页及主导航统一显示“找养老机构”“官方来源”“登记主体”，主搜索进入全国线索目录。全国目录沿用省市、关键词、分页的 URL 状态；卡片主操作打开档案，`from` 限制为安全站内列表路径。原广东页面不再作为独立主导航，但其记录能从全国官方来源页找到。
全国三类目录的首屏先提供省市选择；来源说明与省份捷径排在主操作之后。广东仍是全国选择器中的普通省份选项，旧路径仅用于保留已分享深链。

全国机构线索详情和官方来源详情采用广州档案的双栏结构：页内目录、概况、真实字段、来源、核对建议；右栏提供来源核对入口而非假预约。线索详情另显示同名官方来源与同码主体候选，并保持独立加载、错误、重试和空结果。官方详情只显示其来源实际提供的地址、床位、服务、人数等字段。小屏使用横向页内目录和正文内核对卡，大屏使用左目录与右侧核对卡。来源记录、工商主体和广州官方档案的身份标签始终不同。
全国和广东旧深链的登记主体详情亦使用同一页内目录与双栏布局，保留 37 列原始字段、候选关联和筛选返回；始终标识“登记主体候选”，不把登记主体解释为机构。

## 失败与验证

数据 manifest、城市索引或分块读取失败时保留明确错误和重试；候选关联失败不遮蔽机构档案。无官方候选不等于机构不存在。无来源日期、电话、床位时显示来源未提供或资料时点未知；0 床位保留为 0。覆盖 320、375、768、1440 像素以及键盘/200% 缩放；验证全国入口→省市筛选→详情→官方/主体候选→返回筛选、广东官方记录仍可达、老链接仍可访问。

构建及公开扫描使用项目既有 `npm run verify:local-release`；本机预览按 `NEXT_PUBLIC_ELDERCARE_BASE_PATH=/eldercare` 构建并执行浏览器 smoke check。正式部署仍由用户另行决定。回滚时可恢复导航与详情视图文件，所有原始 JSON 快照保持不变。
