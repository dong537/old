# 腾讯云预览站增量发布设计（2026-11-24）

## 目标与边界

面向维护全国养老机构目录的站点所有者。后续新增、修改或删除来源数据后，仍完整构建并扫描静态站；CD 向腾讯云仅传内容变化的静态文件，保持版本完整、原子切换和回滚。成功标准是相同内容不重复上传、同大小内容变更能识别、删除页面不残留、失败不改变现有站点，线上 release.txt 与提交 SHA 相同。

不按 Git 新增 JSON 直接发布，因为 Next.js 会把数据编入列表、详情、文章与客户端产物。Git push 已按对象增量传输；GitHub Actions 两个作业之间的完整构建归档仍保留，改动范围仅为 Actions 到腾讯云的文件传输。

## 方案取舍

- 继续全量 tar：最简单但本次约 273 MB、服务器上传耗时约半小时，不符合目标。
- 自制文件差量归档：无需服务器 rsync，但需维护路径转义、删除清单和解包覆盖规则，出错面较大。
- 采用 rsync 内容校验与服务器硬链接候选版本：使用成熟工具处理新增、修改、删除。选择这一方案；服务器缺少 rsync 时明确失败，不静默回退全量。

## Source of Truth 与数据流

GitHub main 的提交和构建出的完整 out/ 是发布内容的唯一真源。公开数据先由现有构建脚本生成并经过公开输出扫描；构建作业追加 release.txt、生成每文件 SHA-256 清单，并将完整归档与清单交给部署作业。服务器 current 软链接只指向 /var/www/eldercare/releases 下的已激活版本；它是传输基线，不是内容真源。私有采集目录不进入产物。

部署作业校验归档后在本地解包。远端 prepare 在版本目录下从 current 以硬链接复制候选树并记录原版本；候选目录创建和远端 rsync 进程均固定 umask 022，确保新页面可由 Web 服务读取。rsync -r --checksum --delete 将完整构建树同步至候选树，仅传新增或内容改变的文件，并删除候选树中过期的文件。不能使用 --inplace、--times 或 --perms，避免改变旧版本共享 inode 或因构建时间戳重传。activate 在锁下核对清单、release.txt、首页、404、无符号链接及 current 未漂移，再原子切换 current。smoke check 失败沿用 rollback；未激活候选可 abort 清理。

## 接口、失败与验证

远端脚本提供 prepare、activate、rollback、abort 四个命令，参数为数字 run ID-重试次数和 40 位提交 SHA；activate 另接收仅含校验清单的上传目录。候选版本名由参数确定，拒绝复用；prepare 输出候选静态目录绝对路径供 rsync 使用。abort 只删除从未尝试激活的候选，已激活版本即使回滚也保留。所有操作锁定同一个版本根，不能改变 Nginx 其他站点。服务器与 runner 都必须具备 rsync；缺少时停止部署并保留旧站。当前站点已有 current 基线；新服务器的首次安装沿用既有全量引导流程，不在本次增量脚本内处理。

自动测试用临时版本根验证不变文件零上传、新增、同大小修改、删除、仅时间戳变化、严格默认权限下新文件可读、传输/校验失败不切换、旧版未改写和回滚。CI 保留类型、行为、完整静态构建及公开扫描；部署后核对工作流成功、release.txt、首页、机构目录及从本次构建产物中抽样的详情和文章；纠错页在人工验收中复核。现有手动 workflow_dispatch 与 tencent-preview 环境权限不变。回滚切回上一完整版本，无数据库迁移。
