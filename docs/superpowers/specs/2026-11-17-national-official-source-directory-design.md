# 跨省官方养老服务来源记录设计（2026-11-17）

## 目标与边界

家属可在本地站内按省市查找广东以外已取得的官方逐名来源，打开记录核对原文、资料日期与原始序号；研究者可重跑离线导入并逐行核对。首批为重庆市民政局 1,725 条《养老服务机构》表和苏州市政府发布的张家港市民政监管养老机构 20 条表。广东既有 781 条来源记录继续由原路由提供。成功标准是首批 1,745 行零丢失、同名不合并、每行可追溯，且页面准确区分来源记录、登记主体候选与已核实机构。

这不是全国官方机构全量名录：重庆原表混有养老院、敬老院、社区服务中心和医院，张家港只覆盖该市民政监管机构。重庆网页发布日期为 2025-12-22，未注明资料截止期；张家港网页发布于 2026-10-29，原文注明截至 2026-09-20。两表均不能证明当前在营、空床或服务质量。用户已决定本阶段只做本地版本，不切换线上站点；不新增预约、认领、评分和支付。

## Source of Truth 与字段

开放级别、一般法规和数据集专属许可是不同证据。每次新来源接入前须核对规则在当日是否仍有效、是否已废止或被新规替代，并保存现行条款和该数据集页面；历史指南截图与目录标签不能单独证明当前可下载、商业再展示或逐字段公开。上海 2022 年开放实施细则于 2026-06-08 废止的复核见 docs/research/subagents/shanghai-official-availability-2026-11-17.md 的后续校正。

政府原页决定“发布时写了什么”，保存在 Git 忽略的 `data/private/national-official-source/raw/`。冻结输入分别为：重庆 `157ef38646c9c47a1cae4e802bbb9ffe079f1e087a1591a34bd10095d1c8e76e`（5,416,941 字节）、张家港 `675fe864e615b89f56d6d591ef22035bdbe3b8c52e6d23debfcff1c550aea5dd`（69,789 字节）。来源 URL、标题、发布日、资料期、范围、哈希、行数写入可跟踪的输入清单；公开 JSON 是可重建的投影，不冒充实时官方数据。更新源页必须生成新快照、核对差异，不能静默覆盖。

每条公开记录保存稳定快照 ID、原表序号、省市、名称、地址、来源 ID/URL/发布日期/资料期与范围。重庆的入住人数、从业人数、床位及服务内容仅按原文当时字段展示；空床位保留 null，不把入住人数推算为空床。张家港的床位数按原值展示，电话列不进入公开数据：原表至少 16 条为手机号格式。重庆也不从地址推导区县；同名六组分别保留。数字单元格内部空格只在确认纯数字后去除，并在导入审计记录；不修改原件。

## 模块、接口与数据流

- 离线导入器只读两份冻结 HTML，验证哈希、表头、序号 1…N、列数、必填值、数值及公开字段白名单，输出一个 manifest、省市轻量索引和详情分块。提供生成与 `--check` 只读核对模式；失败不写半成品。
- 领域层只定义官方来源记录的类型、搜索、分页、ID/地区校验和安全返回路径；不读取工商信息，也不推断实体身份。
- 静态 UI 新设 `/quanguo/laiyuan/` 与详情查询页，先选省市再读取对应索引；详情按分块加载，显示原始来源、快照时间、字段未知与局部覆盖警示。广东入口导向现有 `/guangdong/jigou/`，避免重复计数。
- 已批准的企查查跨省候选库继续在 `/quanguo/zhuti/`。若后续生成同省市同名候选关联，必须保留双方来源 ID，标“未核实候选”，不得改写官方记录或登记主体为同一机构；第一批不依赖关系才能发布。
- 数据流：官方网页 → 私有原始 HTML → 冻结哈希/结构校验 → 脱敏公开投影 → 静态 JSON → 来源检索/详情。浏览器只读取公开 JSON，筛选状态由 URL 承载；不存在动态写入、后端权限或本地持久化业务状态。

公开接口固定为 `public/data/national-official/manifest.v1.json`：`{schemaVersion:1,snapshotId,archivedAt,rowCount,sources,provinces}`。每个 source 有 `id,province,city,scope,title,url,publishedAt,asOf,sha256,rowCount`；每个省市清单项有安全 ASCII `slug,name,count,indexPath`。首批地区键为 `chongqing/chongqing` 和 `jiangsu/suzhou`，仅张家港的范围说明随来源展示。城市索引格式为 `{schemaVersion:1,snapshotId,provinceSlug,citySlug,records:[{id,sourceId,rowNumber,name,address,beds,chunk}]}`；详情块格式为同版本/快照/地区及 `records:[{id,sourceId,rowNumber,name,address,beds,residentCount,staffCount,services}]`。张家港不提供的入住、从业与服务内容为 null；原表空床位为 null。每块最多 100 条。客户端只加载 manifest 明示的 indexPath 与其中的安全 chunk 名，拒绝跨快照或跨地区响应；URL 只接受 `province,city,q,page` 和详情 `province,city,id,from`，非法参数给予可见恢复入口。

## 失败、迁移与验证

官方网页返回错误、原件哈希变化、表头/行数/序号漂移、数值无法解释、输出含联系方式或文件缺失时停止导入或构建并显示可恢复错误，不返回空列表假装成功。新目录和 JSON 与广东/工商数据并存，不更改旧 ID 或路由；回滚是移除新路由与新公开快照，旧页面保持原样。原始 HTML 不进入 `public/`、`out/` 或 Git。

验收包含：两份原件哈希、1,745 行与首/中/末原行核对、37 处重庆序号及 26 处数量空格、16 个重庆床位未知、张家港电话全部排除；索引与详情同快照；负例测试覆盖漂移、缺行、联系方式与非法地区/返回 URL。运行类型检查、行为测试、静态导出和公开产物扫描，再在真实浏览器检查首次进入、筛选、详情、返回、空结果/失败恢复和 320/375/768/1024/1440px。原生 200% 缩放尚未验收，不能据窄视口替代；本轮不部署。

## 后续来源扩展（2026-11-17）

在首批两组来源的同一模型与公开隔离契约上，增补福建、湖南、南京、武汉都市圈、石家庄、北京星级和四川南充高坪七组。来源组是清洗与展示单位，不等于单个原始文件；网页与附件可共同构成一组。当前快照 `v1-8f5f79f6f45f99cd` 共 9 组、6,245 条来源行、8 个省级地区和 110 个公开 JSON。每组继续锁定私有原件哈希、原表行序和范围说明，列表与详情只读取公开投影。源文件及联系电话等敏感字段不得进入 `public/` 或 `out/`。

入口仍先选省市范围，再按名称或地址检索；选中的地区、关键词和页码通过 URL 保留，异常详情提供返回入口，加载失败提供可见重试。福建含社区照料设施，北京仅星级参评子集，武汉仅都市圈，南充仅高坪区且含非住养服务点；不能合并为全国或全省当前全量机构数，亦不能由来源行推断当前运营、空床或服务质量。原设计中的 1,745 行和两份原件验收数字只适用于首批阶段；扩展版的最终检查记录见 `docs/verification.md`。
