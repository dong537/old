# 全国省级来源线索静态页实施计划

> 本计划按已授权范围直接执行；仅生成本地静态代码，不部署、不发布 SEO。

**目标：** 为公开线索快照中的31个省级地区提供可直接访问、可分享、可分页的名称与来源行页面。

**架构：** 新增服务端只读校验库，从 `public/data/qcc-institutions/` 的已审核清单与城市索引读取来源。静态导出为 `/quanguo/cankao/sheng/<省slug>/` 和 `/page/<页码>/`；每页20行，记录详情仍链接到现有详情路由和 ID。

**技术栈：** Next.js 15 静态导出、React 服务端页面、TypeScript 与 `node:test`。

## 全局边界

- 来源、名称、地区、地址和床位仅取已审核的 `qcc-institutions` 清单及其引用的城市索引；禁止读取私有研究数据、改动公开投影、builder 或 manifest。
- 41,955 行维持原来源行与 ID；静态导出校验快照、31省分组、索引地区、ID 唯一和来源行连续完整，不合并记录。
- 展示为企查查来源线索；资料时点未知，不能称当前在营、官方备案或全国机构全量。保留 noindex，不部署。
- 除省级入口页链接与详情返回路径外，既有查询路由、详情 ID、候选关联和业务口径不变；无效 slug 不生成路由并返回 not-found。
- 不把全省索引或大数据打入客户端 bundle；城市索引仅在静态生成阶段读取，每页 HTML 最多包含20条。

## Source of Truth 与数据流

`public/data/qcc-institutions/manifest.v1.json` 是快照身份和31省、市级计数及索引路径的权威清单；该清单指向同快照的城市索引，城市索引提供记录名称、原表地区、可公开地址、床位、来源行及稳定 ID。静态生成器从清单加载所有城市索引，校验快照 ID、清单计数、索引地区、全局 ID 唯一，以及 2..41,956 的来源行无遗漏后再按省聚合和排序。路由只持有省 slug 与页码；构建期服务端选择20行并生成 HTML，记录锚点使用原记录 ID、真实省市及安全返回路径进入现有详情页。入口列出清单中31个省级地区链接，不在客户端载入快照。

## 局部 UI manifest

- 用户/频率：家属按省浏览来源行；初次进入及反复回访均可直达分享。
- 主任务/成功标准：打开任一省页可读名称、原表地区、原表地址字段状态、原表床位及来源行；使用20行分页且链接详情可返回同一省和页码。
- 首屏判断：页面标题、快照来源/条数与“非在营/非全量”口径在首屏可见，随后即为20条记录。
- 路由/权限：静态公开路由，继承全站 noindex；不新增登录或写操作。未知省 slug、无效页码均为 not-found。
- 控件契约：省级入口和城市限定是原生可抓取链接；上一页/下一页是带 `rel` 的导航链接；详情仍链接既有详情路由。
- 状态：静态正常、最后一页、未知省份/页码；构建时快照或索引失败即失败，不导出部分省份。
- 极值 fixture：31省、最大省份的页数、20行整页/末页、0床位、暂无可公开地址、长名称/地区/地址、同名多行、兵团地区、未知 slug、重复/缺失行、跨快照索引、`/eldercare` 前缀。
- 视口/验证：目标脚本 `node --import tsx --test tests/institution-reference-static.test.ts tests/institution-reference-search.test.ts` 与 `npm run typecheck:directory`；静态构建由主 Agent 统一执行。人工检查 320/375/768/1024/1440px 及200%缩放，页面不出现横向溢出；本次不重设计现有 tokens。
- 依据：项目全局 AGENTS.md、省级只读静态数据边界及 `frontend-testing-debugging` / `react-best-practices` 技能（2026-11-17）。本次无真实用户测试，浏览器自测结果单独注明。
