## 本机运行

需要 Node.js 20.9 或更新版本。

```powershell
npm install
npm run dev
```

默认打开 `http://127.0.0.1:3000/`，从全国机构线索进入 31 个省级地区。`npm run dev` 与 `npm run dev:directory` 等效，启动真实目录。若要查看 `dist(1)` 本机演示，请单独运行 `npm run dev:prototype`，默认打开 `http://127.0.0.1:3100/guangzhou`；可通过合法的 `PORT` 环境变量调整原型端口。

原型中的机构、服务商、价格、空床、预约、认领和后台流程均沿用虚构演示资料，不代表真实服务或生产功能已完成。状态仅保存在进程内，重启后重置，后台没有真实鉴权；请勿输入真实个人资料或对外部署。原型配置拒绝生产构建与生产启动，所有路由带有 `X-Robots-Tag: noindex, nofollow`，`robots.txt` 禁止抓取。源码来源与边界见 [原型说明](prototype/README.md)。

### 真实机构目录开发

```powershell
npm run dev:directory
```

默认打开 `http://127.0.0.1:3000/`。首页进入全国机构线索、官方逐名来源和登记主体候选三个独立口径；广州 235 家官方名单快照仍可从 `/guangzhou/` 查看。目录筛选、档案与来源说明均不需要外部 API，也不使用原型示例数据。

正式目录另有“养老服务记录”与“长护险指南”。服务记录取自医保官方年度考核表和新增定点评估合格公示，逐行保留来源编号。年度考核表不区分机构护理和居家护理；新增公示不代表已生效；两者都不是当前全量定点名单。

### 真实目录中的对比

在机构列表可用空格分隔多个名称、区或地址线索；每个线索都要命中。勾选2至3家机构后打开“对比已选机构”，对齐查看官方名单中的地址、电话、备案床位和三项预收费标记。选择保存在URL的 compare 参数中，可在筛选、翻页和返回列表时保留；对比页的 ids 链接可复制。此功能不采集个人信息，不推断价格、空床或服务质量。项目的隔离原型中的预约、认领、商户及后台依旧是演示，不属于正式目录。

### 私有工商预览

仅在拥有该机器的用户本机运行：


应用只绑定 `127.0.0.1:3001`。这会从本机忽略的 `data/private/registration_status_all235.csv` 生成私有档案；必须单独手工放入已授权的本机资料。私有模式只适合本机开发预览，不可用 `next build` 生成公开产物。工商公司与养老场所的运营关系没有核实，不可按名称匹配推断已确认运营。

## 数据与构建

后续广东机构主体登记采集仅覆盖有官方养老机构名录线索的 91 企业和 12 事业单位；事业单位法人登记与企业工商登记分开取证。范围、待核清单及限制见[主体登记采集范围](docs/research/2026-11-16-registration-scope.md)。

广州公开脱敏导入 CSV 和稳定 ID 映射位于 `data/raw/`；完整官方原件只保留在 Git 忽略的 `data/private/`。公开 CSV 中六处手机号格式的原表号码已替换为 `[已遮蔽]`，导入器仍保留“原表有号码但暂不展示”的语义。广州公开构建输入仅来自这两份公开文件。省级页面读取独立的公开 JSON 投影，不读取私有研究包。可复核导入数量／异常与公开副本 SHA-256：

```powershell
npm run data:build
npm run data:private
npm test
npm run typecheck
npm run build
npm run verify:release
```

`data:build`生成官方静态机构JSON及导入报告；`services:build`离线验证归档中的医保官方HTML及SHA-256后生成服务记录JSON。`data:private`还会写入Git忽略的本地工商派生快照，之后只由`npm run dev:private`使用。`typecheck`分别检查真实目录与本机原型。`build`与`preview`构建并预览全部正式静态目录，不包含本机原型。公开生产构建会强制官方模式，生成`out/`后扫描HTML、JS、JSON、CSS等输出中的私有字段特征、本机已知信用代码及暂不公开的官方来源手机号。企查查的版本化 JSON 按各自精确字段集合校验；获授权原表的全部列名仅保存在详情的 `sourceFields` 对象；手机号、其他电话、邮箱及嵌入自由文本的联系方式在公开快照中整格遮蔽。私有原件、未批准字段及未授权的查企GO快照仍被阻断；整理后的索引和登记字段维持原有校验。扫描失败表示不能发布。`verify:release`依次运行类型检查、完整测试和静态生产构建，GitHub Actions会在push和pull request上执行该门禁。

更新官方名单时，不要覆盖旧输入后直接发布。先存档旧快照与JSON、核对民政局来源、手工复核`id-map.json`中的“来源序号→档案ID”对应，维持既有ID或单独处理新增、撤销、合并的机构，再执行导入测试和差异审阅。未来名单行序变化时可显式修订映射，以机构身份保留URL。床位、名称、收费字段按新源重建，不保留过期数据。

本机生成静态公开预览：

```powershell
npm run build
npm run preview
```

打开 `http://127.0.0.1:3000/guangzhou/`。这只读取静态产物用于验收；生产部署应由静态托管平台直接托管 `out/`，不部署该Node预览脚本或运行时服务。当前尚无正式域名和公众联系/纠错渠道。

## 广东 21 市公开来源记录

省级入口为 `/guangdong/jigou/`。本次从第十五批冻结研究包的 2,429 条跨期观察中，按城市、官方来源 URL 和证据类型精确选取每市一份逐名来源，生成 781 条公开来源记录。每条只展示原文名称、城市、来源、发布日期、原文明示的资料期及来源当时的状态警示；记录编号不是机构 ID，781 不是独立机构数或在营机构数。来源混有长者服务中心、医院等名称，部分市只有一个区县子集。广州海珠 30 条与既有广州 235 条名称重合，不能相加为新增机构。

公开投影保存在 `public/data/guangdong-source-records.v1.json`，公开构建只读取它；`data/private/` 中的原件、未公开工商资料和明细永不进入网页。持有本地冻结归档时，可运行 `npx tsx scripts/build-province-public.ts --check` 核对输入哈希与投影；更换来源前需另做审阅并重新生成。当前 114 条缺原页逐行 SHA、167 条缺可定位源行号，未核实全省当前在营状态；无正式域名和公众纠错渠道，继续保持 noindex。

## 广东登记主体候选库

在 `/guangdong/zhuti/` 单独检索企查查于 2026-11-16 导出的 6,777 条广东登记主体宽口径搜索结果，可按名称、城市、主体类型和登记状态筛选。其中存在与养老服务关联未核实的记录，既不等于 6,777 家养老机构，也不能证明主体当前运营某个养老场所。官方来源详情仅对同城同名的 157 条来源记录显示 158 个主体候选引用；一条来源可能关联两个不同主体，关系未核实。

原 XLSX 留在 Git 忽略的 `data/private/`；`python scripts/build-qcc-public.py` 离线生成 `public/data/qcc/` 内最小索引、分块详情和候选关联，`python scripts/build-qcc-public.py --check` 核对冻结输入和公开投影。列表与检索继续使用整理后的字段；详情的 `sourceFields` 保留全部 37 个列名和非联系字段原值；手机号、其他电话、邮箱及含联系方式的自由文本显示“[已遮蔽]”，网址、邮编和行业分类等仍按原表展示。原表空值、空字符串及占位值不会被整理字段替代。92 条缺统一社会信用代码、2 条代码未通过校验位，不推断为有效登记身份。页面展示来源导出日期和原表行号；公开版不展示原始联系方式，联系机构时请使用其当期官方渠道核实。

与查企GO登记照面 25 项相比，该导出有 14 项可直接对照、4 项需保留原值后映射，仍缺实缴资本、纳税人资质、人员规模、核准日期、登记机关、进出口企业代码和企业简称这 7 项或不能等价替代；“企业规模”不等于“人员规模”。工商登记状态不代表养老机构营业状态。设计和验收口径见[接入方案](docs/superpowers/specs/2026-11-16-qcc-registration-directory-design.md)。

## 跨省登记主体候选库

用户提供的 25 份企查查高级搜索 XLSX 经审核后生成独立的跨省候选目录，入口为 /quanguo/zhuti/。源文件合计 141,364 行、覆盖广东以外 30 个省级地区与 320 个省市组合；广东旧快照仍在 /guangdong/zhuti/，全国页在省市选择器前提供广东独立入口，因此大陆 31 个省级地区均可分别查询候选记录。两批快照口径不同，不直接相加为机构数；这些记录不是全国备案养老机构数量，也不证明当前营业或服务质量。官方来源另有广东及下列跨省局部资料；线索与登记主体只建立待核候选关联，尚未确认场所运营关系。

源 XLSX 不随网站发布。输入文件的 SHA-256 和逐文件行数锁定在 data/raw/qcc-national-source-manifest.json；脚本离线验证标题、数量、代码状态和地区分布，再输出 public/data/qcc-national/ 下的 manifest、320 个城市索引及详情分块。各详情的 `sourceFields` 保留全部 37 个原始列名及非联系字段原值；手机号、其他电话、邮箱和含联系方式的自由文本整格显示“[已遮蔽]”，其余企业简介、网址、邮编与行业分类按原表展示；网址不自动转为外部链接。精简索引、规范化字段、地区分组和候选关联保持原有口径，原始字段不会提升为已核验或实时资料。原件漂移会使显式 `--check` 失败；发布构建扫描按精确字段集合阻断未批准字段、原始字段内外的联系方式、分片缺失及与锁定清单不一致的行覆盖。发布前必须同时执行下述 `--check` 与 `verify:release`。

本机数据更新与复核命令（先安装 requirements-data.txt 中的依赖）：

    python scripts/build-qcc-national.py --source-dir "C:/Users/Lenovo/Desktop/search/example"

    python -m unittest tests.test_qcc_national -v

静态站首屏仅读取约 44 KB 的 manifest，选定城市才读取城市索引，打开详情才读取相应分块。未经复核的新批次不能只替换 XLSX 或 JSON；需更新锁定清单、审计差异及快照后重新构建。设计边界见 docs/superpowers/specs/2026-11-16-national-qcc-candidate-directory-design.md。

## 全国养老机构来源线索（本地）

本地新增 /quanguo/cankao/，读取用户提供、确认有公开展示授权的企查查《养老机构信息.xlsx》。冻结原件 SHA-256 为 6bc157e2695965ed8b1c85e82f6f8b7fa7d13102149f9f1512e9863b2489fd81；公开快照 v1-4ab89d0a078c4e13 保留 41,955 个原表工作表行号，按原表行政区划代码和“地区”交叉核验后分为大陆 31 个省级地区、375 个地市展示组。它是来源线索，不是 41,955 家已核实、当前在营或全国完整的养老机构；原件未标逐家资料截至日，本地接收日期不能代替资料日期。原始 XLSX 保持在 Git 忽略的 data/private/qcc-institution-reference/，不会随站点发布。

原表后加“省份”列有 1,311 行空值、7,086 行与行政区划代码冲突；检索分组仍只用相互一致的代码与“地区”。详情的 `sourceFields` 保留全部 11 个列名与非联系字段原值，包括补充省市区、经纬度、地址和无效或占位代码；含联系方式的自由文本整格显示“[已遮蔽]”。这些原值不用于覆盖地区分组、生成导航或有效代码关联。地址原空 600 行、含联系方式而遮蔽 604 行、与机构名称相同的占位 127 行，列表地址共 1,331 行显示“暂无可公开地址”；详情中 604 个含联系方式的地址也已遮蔽。原表床位 0 保留为 0，床位数不是当前空床。整理后的信用代码只保留经格式和校验位验证的 39,360 行（其中 101 行原表小写字母转大写）；其余 19 行缺失、549 行全零占位及 2,027 行无效代码仍保留对应状态，原始值单列展示。相同名称或代码不能自动合并机构。

独立的同省同名候选关联快照 v1-66b9167d3d2cdd6b 从本表、跨省官方来源和广东官方来源的公开投影离线生成：5,501 条线索行有 5,513 对名称候选（跨省 5,036、广东 477）。它仅帮助打开双方来源记录，不证明是同一机构或仍在营；无匹配也不证明机构不存在。地区文件、目标记录与三份输入快照由公开扫描器核验。主体与机构的分层核对见 [对应关系核查](docs/research/subject-institution-mapping-2026-11-17.md)。

独立的同省有效信用代码候选快照 v1-4e0d5823e078f6cb 将 7,541 条机构线索行指向 7,287 个不同的工商目标；另有 1 条唯一代码命中因跨省未公开关联。147 个工商目标对应多条线索，最多 18 条，不能用关联行数或目标数代替机构数。同一代码只表示可核对的登记主体候选，不证明是同一养老场所、当前运营者或官方备案机构。详情页在独立区块加载此关联，失败可重试，关联加载失败不影响核心线索详情。私有原件保留原值，公开详情中的联系方式仍按规则遮蔽。

## 真实目录技术栈与路由

- Next.js 15.5 + React 19 + TypeScript + Tailwind CSS 3；静态导出，详细档案预生成。
- `/guangzhou/`：广州入口；`/guangzhou/jigou/`：广州名单检索与分页；`/guangzhou/duibi/?ids=...`：2至3家广州官方字段对比；`/guangzhou/jigou/gz-000001/`：广州档案；`/guangdong/jigou/`与其记录页：广东21市官方逐名来源索引；`/quanguo/laiyuan/`与详情页：跨省已核官方来源行；`/guangdong/zhuti/`和`/quanguo/zhuti/`：独立登记主体候选库；`/guangzhou/shangmen/`：官方服务记录；`/guangzhou/changhuxian/`：长护险指南；`/rules/`：来源和限制。公开 JSON 分别保留各自快照和字段边界。
- 默认不收录搜索引擎：公开HTML为 `noindex`，待域名/授权/正式发布条件具备后，方可单独改动并复核。

数据来源与限制详见[蓝图](docs/blueprint.md)和[设计契约](docs/design-contract.md)；页面与 `dist(1)` 的逐项对照见[视觉还原验收记录](docs/research/prototype-fidelity-continuation-2026-11-15.md)。真实目录只保留首期有真实数据支撑的能力；上门服务、商业后台、预约与榜单虽可在隔离的本机原型中演示，但正式业务仍须在取得真实名单与授权、完成持久化及权限等能力后另行实施。
